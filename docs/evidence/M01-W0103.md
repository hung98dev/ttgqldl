## CI failure and repair (run 41648149782)
The first CI run for this work package failed in the `schema and postgres 18.6
integration` step. Reproduced locally against a freshly created, superuser-owned
database (exactly the CI shape):

```
--- FAIL: TestSchemaContractTables
    schema_test.go:92: schema public contains 1 table(s); migrations must stay in ttg
```

Root cause: goose creates its own `goose_db_version` table **before** the first
migration, in the connection's default `search_path`. The development role
`ttg_owner` has `search_path = ttg` set by the container bootstrap, so the table
landed in `ttg` locally; the CI service container connects as `postgres` with the
default `"$user", public`, so the bookkeeping table landed in `public`. The
assertion was correct and caught a real portability defect.

Repair: `cmd/migrate` now creates the owned schema explicitly and pins
`search_path=ttg` on its own connection (URL and keyword DSN forms) before goose
runs. Verified on a fresh database:

```
$ migrate -direction up      → OK 00001 / 00002 / 00003, version 3
$ information_schema.tables group by table_schema
  ttg|20          ← 19 domain tables + goose_db_version
  (public absent)
$ go test -v ./test/integration/...  → all six tests PASS as the CI role
```

The failure is retained here because "green after a fix" is only meaningful with
the failing observation on record.

## Remediation — Task 003 (schema contract gaps closed)

The original record above is preserved unchanged apart from the inventory
heading. Two authoritative requirements from 04_DATABASE.md were **not** covered
by migrations 00001–00003, and the sqlc drift guard only compared table names.

### Gap 1 — `actor_identity_aliases` was entirely missing
Required by 04_DATABASE.md ("Privacy restore ledger and HMAC rotation"). Without
it, HMAC key rotation cannot preserve permitted player continuity and the
identity contract had no database representation.

Created by `00004_identity_aliases.sql` (additive; 00001–00003 untouched) with
the binding invariants now stated in 04_DATABASE.md:

| Invariant | Mechanism |
|---|---|
| `actor_key` is a scoped pseudonym, never a raw provider id | `CHECK (actor_key ~ '^[0-9a-f]{64}$')` |
| `key_version` names a secret generation, never a secret | `CHECK (key_version ~ '^[A-Za-z0-9._:-]{1,32}$')` |
| The mapping is unique per (village, actor, key version) | `PRIMARY KEY (village_id, actor_key, key_version)` |
| The player must exist **in the same village** | `UNIQUE (village_id, id)` on `players` + composite FK `(village_id, player_id)` |
| Erasing a player cannot leave a live pointer | `ON DELETE CASCADE` on the composite FK |
| Village deletion is refused while mappings exist | `ON DELETE RESTRICT` on `villages` |
| Resolution and erasure lookups | PK (identity resolution) + `actor_identity_aliases_player` index |

### Gap 2 — no transactional export state for the deletion ledger
04_DATABASE.md requires each deletion to be exported atomically to an
independent encrypted ledger, but the schema only had `privacy_tombstones`;
there was no way to prove that the external ledger acknowledged an event.

Created `privacy_ledger_outbox` (same migration): identity `seq` for export
ordering, `tombstone_id` FK, JSONB `payload`, `exported_at`, `ledger_ack_ref`,
`attempts`, `last_error`; constraints `(exported_at IS NULL) = (ledger_ack_ref IS
NULL)`, `attempts >= 0`, `jsonb_typeof(payload) = 'object'`; partial index on
`seq WHERE exported_at IS NULL` for the exporter scan.

**Scope boundary:** M01 delivers the database-side outbox only. The encrypted
append-only ledger, fsync/durable acknowledgement, the exporter worker, restore
replay and the fail-closed restore gate remain **M04-W0406** work. Nothing in
this record claims privacy restoration is verified.

### Rollback safety
The 00004 down migration fails closed with a `RAISE EXCEPTION` while identity
mappings or unexported deletion events exist, and only removes the objects on an
empty disposable database. Production rollback therefore cannot silently destroy
continuity or erasure evidence; the operator must export or resolve deliberately.
Verified in `TestMigrationLifecycleDestructive`.

### Honest limits after remediation
- The outbox has no exporter, retry policy or ledger implementation yet (M04).
- The fingerprint is PostgreSQL-18-specific because PostgreSQL 18 materialises
  NOT NULL constraints in `pg_constraint`; the stack is pinned to 18.6.
- Column-level drift is now detected by the fingerprint, but the fingerprint
  itself must be regenerated deliberately; CI fails rather than auto-fixing.
- `TestAppRoleCannotRunDDL` and `TestRolesAreLeastPrivileged` skip when the
  connection is not the `ttg_app` role, so they prove nothing on a superuser DSN.
