# M02-W0207 - Wave settlement, victory/defeat, rewards, penalties, recovery and XP

Settlement and XP implemented in the authoritative boundary pipeline
(`simulation/settle.go` + `resolveBoundary`). Pure Go, checked int64, no floats,
no I/O, no separate reducer.

## XP contract

At each positive multiple of 200 through 2800, before economy/combat:

- active members with `joined_tick <= tick` and `xp_awarded == false` gain 10 XP;
- the session cap of 300 is respected exactly (295 -> 300, never 305);
- `xp_awarded` marks the member for the rest of the wave;
- no XP at tick 0, for pending members, for votes or for repeated messages;
- XP is awarded before the fatal combat of a boundary and preserved on defeat;
- session XP persists across rollover.

## Settlement at 2800

Ordering: due role/vote application, XP, economy/repair/upgrade, boss spawn,
final combat, settlement, then the phase notification. Settlement runs exactly
once and only after final combat; a second attempt is a no-op with no events and
no resource change.

Victory requires all of: townhall > 0, all ordinary pools 0, and on boss waves a
spawned boss at 0 HP. Victory applies +100 wood, +60 stone, +50 food (capped),
win streak +1 (cap 10), losses 0, total wins +1, level `min(50, 1+wins/3)`.
Loss applies win streak 0, loss streak +1 (cap 3), and penalties
`floor(resource/5)` computed from pre-penalty stocks; if the vote closed with C,
each penalty is halved with floor; resources never go negative. Recovery floors
(`wall >= 250`, `townhall >= 250`, `wood >= 100`, capped) apply only when the
townhall actually reached zero, after penalties. `wave_result` is emitted once
with the settled result.
