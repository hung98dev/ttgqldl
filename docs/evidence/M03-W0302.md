# M03-W0302 — Deterministic mock and replay source adapters

Status: **PASS**. This package implements the source abstraction, the seeded mock
source, the versioned NDJSON replay source, cursor/reconnect/delivery lifecycle,
validation and the test-only parser bridge. It does **not** implement identity
hashing, durable ingestion, production deduplication, metrics, the 10k population
load test or any TikTok/live provider access. W0303–W0308 remain NOT_STARTED.
QA-SEC-06 (alias moderation/XSS/offensive-content audit) is **not** claimed here; it
remains owned by the M05/M08 threat gates.

## 1. Source contract

`backend/internal/source` exposes the binding contract as an interface:

```go
type Source interface {
    Start(ctx, session, sink) error
    Stop(ctx) error
    Health(ctx) Health
    Capabilities(ctx) Capabilities
    Reconnect(ctx, cursor, sink) error
}
type Sink func(ctx context.Context, event Event) error
```

- One adapter per session; `Start`/`Reconnect` deliver synchronously on the caller's
  goroutine until EOF, cancellation, operator Stop or delivery failure. No goroutine
  is spawned inside the adapters.
- `Sink` returning an error is backpressure/rejection: delivery stops, the cursor is
  not advanced and `Health.Status` becomes DISCONNECTED (retryable interruption).
  A callback failure is never silently skipped.
- Start is legal only from NEW; repeated Start returns `ErrAlreadyStarted`. Stop
  before Start records STOPPED and a later Start is refused. Reconnect is legal only
  after EOF, DISCONNECTED or STOPPED.
- Stop cancels the run context (so a blocked sink can return) and waits for the
  emission loop to exit; after Stop returns no callback is running or can start.
- Sources never claim durable exactly-once ingestion. Durable acknowledgement remains
  W0305; the cursor is a source position, not a database commit.

Types: `Mode` (mock/replay/authorized_live-recognized-but-unimplemented), `Session`,
`Event`, `EventKind` (comment/gift/like/share/follow/join), `Capabilities`, `Health`,
`Status` (NEW/RUNNING/STOPPED/EOF/DISCONNECTED/FAILED), `TimestampReliability`,
`RateLimits`, `Cursor`, `RecordError` and stable sentinel errors.

## 2. Validation and privacy boundary

`ValidateEvent` rejects: session/provider mismatch, unknown event kind, invalid UTF-8,
comments over 500 bytes, controls/format characters in messages, identifiers over 256
characters or containing controls/bidi, aliases over 64 grapheme clusters (conservative
upper-bound counter), aliases with controls/bidi/leading marks/more than 16 marks, and
more than 1024 alias bytes. Whitespace controls and Unicode separators are allowed in
messages; command grammar is **not** interpreted by the source layer. Only
`event_kind=comment` may produce a command; gift/like/share/follow/join events are
delivered but the bridge ignores them.

Errors and `Health.LastError` expose stable categories only; raw comments, aliases and
provider event/viewer ids never appear in public error text. Tests assert the malformed
fixture error and health contain no `viewer-0001`, `event-0001` or session id.

## 3. Mock source

`MockConfig{Session, Seed, Scenario, Count}`; `NewMock` and `NewMockWithEvents` accept
explicit deterministic scripts. The adapter source identity is SHA-256 over the session,
event count and the canonical event fields; it binds cursors to the exact script.
Synthetic event/viewer ids are derived from the seed with SHA-256 and prefixed
`mock-`/`mock-viewer-`; timestamps use a fixed epoch plus event index (no wall clock,
no `math/rand`, no global state). Identical configuration yields identical events;
different seeds produce reproducibly different synthetic ids.

Reviewed scenarios: single registration, multiple participants, repeated comments,
role changes, votes A/B/C, invalid comments, Unicode variants, duplicate provider event
ids, out-of-order upstream timestamps, non-comment events, empty, finite script.
`MaxMockEvents` = 1,000,000 bounds memory; the 10,000-participant acceptance remains
W0307.

Capabilities: stable synthetic viewer/event ids, replay cursor, delivery order,
synthetic deterministic timestamps, display name; moderation events false; rates
unspecified. Mock is never described as an authorized provider identity or a real
viewer population.

## 4. Replay source

`ReplayConfig{Session, Directory, Fixture}`. `NewReplay` reads `manifest.json`
(strict decoding, unknown fields rejected, schema 1), resolves a plain fixture file
name (path traversal rejected), hashes and counts the fixture in a bounded streaming
pass, verifies the manifest SHA-256 and record count, and only then allows delivery.
The SHA-256 digest is the adapter source identity, so a cursor from one fixture cannot
select a position in another.

NDJSON record schema (schema_version 1):

```json
{"schema_version":1,"source_session":"...","event_seq":1,"provider":"replay",
 "provider_event_id":"...","provider_viewer_id":"...","alias":"...",
 "message":"XÂY","event_kind":"comment",
 "received_at":"2026-01-01T00:00:01Z","upstream_at":"..."}
```

`received_at`/`upstream_at`/ids/alias are optional (message required for comments as
usual; empty message is source-valid but parser-invalid). Strict rules: UTF-8 validity
of the whole line, JSON syntax, unknown fields rejected, schema version exactly 1,
`event_seq` exactly consecutive from 1 (duplicates/gaps rejected), provider exactly
`replay`, session must match, event kind known, timestamps RFC3339Nano when present.
Records are delivered in file order; upstream timestamps are never used for sorting.
Malformed records are never skipped: delivery stops with a `RecordError` carrying the
exact line and record number (1-based). EOF is deterministic and terminal; reconnect
re-opens and re-verifies the same fixture. No fallback to mock exists.

Bounds: 64 KiB per record (`ErrRecordTooLong`), 1 MiB manifest, 32 KiB hashing buffer,
line-by-line streaming (no whole-file load). A generated 50,000-record fixture streamed
in 94 ms after the task-034 verified-snapshot change (81 ms before it) and resumed at
position 49,999 in the test run.

## 5. Cursor contract

Versioned format `ttgc1.<base64url(session)>.<base64url(sourceID)>.<nextEvent>`.
`nextEvent` is the 0-based index of the next event to deliver (delivered count), never a
wall-clock value. `ParseCursor` rejects unknown magic/version, malformed base64, empty
components and non-numeric positions. `Reconnect` additionally requires the session and
source identity to match (`ErrCursorMismatch`) and the position to be within the source
(`ErrInvalidCursor`). Initial cursor = position 0; EOF cursor = event count. Reconnect
at EOF delivers nothing and ends at EOF. Tests cover another session, another fixture,
unknown version, out-of-range position, repeated reconnect, reconnect after
cancellation and reconnect after callback failure.

## 7. Health and capabilities

Health is separate from the game lifecycle and exposes Status, Delivered (cumulative
successful deliveries for this adapter instance), Cursor (next position) and a stable
LastError category. Statuses: NEW, RUNNING, STOPPED, EOF, DISCONNECTED, FAILED.
Callback rejection is DISCONNECTED (retryable) with cursor before the rejected event;
malformed fixtures/read failures are FAILED. The simulation pause-reason contract
remains authoritative; a disconnected source never auto-resumes gameplay.

Capabilities are truthful and static per adapter: mock declares synthetic stable ids
and synthetic deterministic timestamps; replay declares fixture-stable ids and recorded
timestamps; both declare cursor, delivery order and display name, no moderation events,
and unspecified rates. No capability claims provider authorization.
