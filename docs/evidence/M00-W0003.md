# M00-W0003 — Official stable version verification for Go, PostgreSQL and Unity

## Claim under test
01_PRODUCT_SCOPE.md pins Go 1.27.3, PostgreSQL 18.6 and Unity 6000.6.7f1 as the reproducible baseline. A pin is only meaningful if it names a real, current, officially published release.

## Sources consulted (2026-11-03)
| Source | Observation |
|---|---|
| https://go.dev/dl/ | "Stable versions: go1.27.3". Published artefacts include `go1.27.3.windows-amd64.msi` (SHA256 `89ec8325f667c674fe1b94a5a88e26932aa12323589881927ff54da99d4b7faa`) and `go1.27.3.src.tar.gz` (SHA256 `6e7749035cf360f06b2575d162ea79df9fda8ef671889e5c375f8e50777f26bb`). go1.26.10 is also listed as a stable 1.26 line. |

| https://www.postgresql.org/about/news/postgresql-19-rc-1-released-3409/ | Site banner dated 2026-10-15: "PostgreSQL 19 RC 1 Released" — PostgreSQL 19 is still a release candidate, so pinning the 18 line is the stable choice. |
| https://unity.com/releases/editor/whats-new/6000.6.7f1 | HTTP 200, page title "Unity 6000.6.7f1", i.e. the exact pinned editor release exists in the official release archive. |

## Result
All three pins name real, currently published releases. **PASS** for the verification objective.

## Environment divergence (recorded, not hidden)
- The workstation has **go1.27.1**, not the pinned go1.27.3. The tooling module declares `go 1.27.0`, so it builds and tests on the older patch, but CI and M01 `tooling/doctor` MUST fail on a version other than 1.27.3. This is an environment gap, not a specification defect.
- **No PostgreSQL server is installed**, so no SQL migration, constraint or transaction test could run. Every database claim in M00 is a design review only.
- Unity was not launched, so no scene, FPS, licence or OBS claim is made.
- Consequence: QA-GOV-02 (exact pinned versions and digests in the build) can only be satisfied at M01 when the pins are machine-enforced; the M00 contribution is the verified pin values themselves.
