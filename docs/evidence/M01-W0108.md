# M01-W0108 — Secure configuration templates and typed startup validation

## Deliverable
`.env.example` as the only committed environment template, a typed Go config
that implements the whole 08 register with fail-closed validation, and ignore
rules that keep real credentials out of the repository.

## Files
- `.env.example` — the register with development placeholders only:
  `TTG_ENV`, `TTG_SOURCE`, `TTG_HTTP_ADDR`, `TTG_LOG_LEVEL`,
  `TTG_SHUTDOWN_TIMEOUT`, `TTG_READINESS_TIMEOUT`, `TTG_METRICS_ADDR`,
  `TTG_MAX_QUEUE`, `TTG_STREAM_RATE_HZ`, `TTG_SNAPSHOT_TICKS`,
  `TTG_HMAC_KEY_VERSION`, `TTG_HMAC_SECRET`, the PostgreSQL bootstrap/app/owner
  passwords, `POSTGRES_PORT`, `POSTGRES_DATA_VOLUME`, `TTG_DATABASE_URL`, and
  commented placeholders for the stage/prod-only secrets.
- `backend/internal/config/config.go` — `Load(getenv func(string) string)` returns
  a typed `Config` or `errors.Join(ErrInvalid, *FieldError…)`; `getenv` is
  injected so the loader never reads the process environment itself.
- `backend/internal/config/dotenv.go` — minimal, strict `.env` parser plus
  `ApplyDotEnv`, which never overrides an existing process variable.
- `.gitignore` — `.env`, `.env.*` (with `!.env.example`), build outputs,
  coverage, caches, `go.work`, editor noise.
- `.gitattributes` — `*.sh`, `*.sql`, `*.yaml`, `go.mod`, `go.sum` forced to LF
  so a Windows checkout cannot produce a CRLF shebang inside a container.

## Validation rules implemented
| Field | Rule |
|---|---|
| `TTG_ENV` | `dev`\|`stage`\|`prod`, default `dev` |
| `TTG_SOURCE` | `mock`\|`replay`; `authorized_live` is **refused** while GATE-LIVE is blocked |
| `TTG_HTTP_ADDR` / `TTG_METRICS_ADDR` | explicit host:port, port 1–65535 |
| `TTG_DATABASE_URL` | required everywhere; `postgres://`/`postgresql://`; host and database name required; `sslmode=disable` refused outside dev for a non-loopback host |
| `TTG_LOG_LEVEL` | `debug`\|`info`\|`warn`\|`error` |
| `TTG_SHUTDOWN_TIMEOUT` | Go duration, `>0` and `<=5m`, default `10s` |
| `TTG_READINESS_TIMEOUT` | Go duration, `>0` and `<=30s`, default `2s` |
| `TTG_MAX_QUEUE` / `TTG_SNAPSHOT_TICKS` | positive integers with documented defaults (20000 / 600) |
| `TTG_STREAM_RATE_HZ` | 1–10, default 5 |
| `TTG_HMAC_KEY_VERSION` / `TTG_HMAC_SECRET` | required in every mode; secret ≥32 bytes |
| `TTG_ADMIN_PASSWORD_HASH` | stage/prod required, must be an Argon2id PHC string (`$argon2id$…`) |
| `TTG_STREAM_SIGNING_SECRET` | stage/prod required, ≥32 bytes |
| `TTG_SOURCE_CREDENTIAL_REF` | parsed; only meaningful for `authorized_live`, which is refused |

## Tests and results
```
cd backend && GOTOOLCHAIN=auto go test -count=1 ./internal/config/
ok  github.com/hung98dev/ttgqldl/backend/internal/config   coverage: 93.9% of statements
```
Covered: documented defaults; explicit values across two modes; **19** invalid
cases (unknown env, unknown source, `authorized_live`, malformed address, port
range, empty host, bad log level, unparseable/negative/excessive durations, zero
readiness timeout, out-of-range stream rate, non-numeric queue, short HMAC
secret, empty HMAC key version, wrong URL scheme, missing database name, missing
host, empty database URL); stage/prod requiring admin hash and signing secret;
Argon2id format rejection; `sslmode=disable` refusal for a remote host with
loopback still allowed; multiple problems reported in one error; nil `getenv`;
dotenv quoting/comments/`export`/empty values; malformed dotenv lines; missing
file is not an error; process environment is never overridden.

## Secret hygiene
- `git status` shows `.env` untracked and ignored; the commit contains only
  `.env.example` with the literal placeholder `dev-placeholder-replace-me`.
- The startup log never prints a secret: only `env`, `source`, `version`,
  `http_addr` and a fixed note. Configuration errors name the **variable**, never
  its value.
- A repository scan for common credential patterns over the staged files found
  no matches (see M01-W0101/W0107 command logs).

## Honest limits
- No secret scanner (gitleaks/trufflehog) is wired yet; W0106 owns the CI
  security stage.
- `TTG_ADMIN_PASSWORD_HASH`, `TTG_STREAM_SIGNING_SECRET` and
  `TTG_SOURCE_CREDENTIAL_REF` are validated but not consumed: authentication is
  M05/M07, signing is M05, the LIVE adapter is M10.
- The development `.env` uses placeholder passwords bound to 127.0.0.1; stage and
  production must inject real secrets and must not ship this file.
