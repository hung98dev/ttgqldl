## Transactional ordering preserved as specified
- Ingest: validate → lock session row → allocate `input_seq` → `scheduled_tick = committed_tick+1` → insert provider receipt → append immutable event → commit → acknowledge. No authoritative mutation is acknowledged before commit.
- Reducer: `SELECT … FOR UPDATE` + fencing-epoch compare → apply unprocessed events for the boundary → mark each event applied (including no-op/cooldown outcomes) → advance tick → write state + outbox + domain events in the same transaction.
- Recovery: checkpoint → verify hash → replay accepted inputs up to the committed boundary → never advance on wall clock.
