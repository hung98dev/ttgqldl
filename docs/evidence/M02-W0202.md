# M02-W0202 - Deterministic tick state machine, lifecycle and rollover control

Pure logical progression layer under ackend/internal/simulation. It owns the
clock, lifecycle, pause reasons, phase boundaries, rollover control and
deterministic transition events. It implements no combat, vote, economy, XP,
persistence or network work.

Every call validates its input state, works on a deep copy, validates the result

## Tick rules implemented

- WAITING is tick -1 and cannot advance.
- A wave starts only from an explicit accepted registration at tick 0; operator
  START alone, a timer or a fabricated participant can never start it.
- Exactly one tick per dvance_tick; stale FromTick requests are rejected.
- Phase is derived from the tick on every transition; no separate phase clock.
- Tick 3000 is reached by one advance but only a rollover consumes it, and no
  gameplay resolution runs there (no phase change, no settlement).
- Entering tick 2800 emits settlement_required and leaves the result pending:
  W0202 never settles a wave or sets a victory.
- Pause reasons freeze the tick; clearing one of several does not resume; clearing
  all resumes with no catch-up ticks.
- Rollover: exactly one wave increment, wave state reset, village/XP/streaks
  preserved, pending registrations promoted with joined_tick=0, running at tick
  0 when the queue is non-empty, otherwise WAITING at -1. A paused session cannot
  roll over until resumed.
