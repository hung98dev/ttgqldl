# M03-W0307 — 10,000 unique mock participants and deterministic ingestion

Status: **PASS** for W0307's 10k population, identity, classification and durable
verification. W0307 is **not** M08-W0801 and does not claim sustained 1k/s, 5k/s burst,
10k concurrent real viewers, production latency SLO, reducer-applied roles, or published
latency.

## 1. Scope and boundaries

Existing `ScenarioMultipleParticipants` and the existing HMAC identity primitives were
reused; no second population generator was added. No production code changed. New tests
cover:

- deterministic 10 / 100 / 1,000 / 10,000 participant generation;
- 10,000 unique synthetic viewer IDs, event IDs and scoped ActorKeys;
- exact cyclic role distribution (3,334 / 3,333 / 3,333);
- 10,000 real PostgreSQL inserts through the real W0305 Batcher;
- source cursor/ACK contract at 1,000 events (synchronous `Mock.Start` + real Batcher,
  fake durable appender);
- 10,000-event interrupted source and reconnect;
- redelivery after a fresh deduper, proving PostgreSQL receipts remain authoritative;
- 10,000 mixed inputs with exact category counts;
- 1,000 comments from one actor with no identity inflation;
- metrics, queue bounds and privacy at scale.

**Boundary disclosure:** the 10,000 durable test uses the direct W0305 Batcher boundary
after real source generation, `source.ValidateEvent`, HMAC identity, parser and W0304
dedupe. It does **not** claim a full asynchronous `Mock.Start → durable` runtime pipeline.
The mock sink is synchronous and returns one ACK at a time, so a serial source callback
would create one-row batches and take minutes; changing that would violate cursor/ACK
semantics. Source cursor and ACK ordering are proven separately at 1,000 events with the
real batcher and a fake appender, and the source is proven to deliver all 10,000 events
with validation in `TestScenarioTenThousandDeliversEveryValidEvent`.

## 7. Defects and limitations

No new production correctness defect was found in W0302–W0306. The audit confirmed the
known synchronous source constraint: `Mock.Start` invokes one sink at a time and
`Batcher.Submit` waits for durability, so a naive 10k serial run flushes one-row batches
and is impractically slow. W0307 does not weaken ACK/cursor semantics to hide this; it
uses the direct batcher boundary for 10k durability and separately proves source
cursor/ACK at 1,000 with the real batcher.

Not claimed: reducer-applied roles, registration/XP, M04 persistence, M07 dashboard,
M08 sustained load, 10k real concurrent TikTok viewers, OBS/Unity FPS, production SLO.
