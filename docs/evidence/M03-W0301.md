# M03-W0301 — Exact Unicode command parser

Status: **PASS**. This package implements only W0301. W0302–W0308 remain
NOT_STARTED; QA-CMD-02/03/04 are stateful dedupe/admission/cooldown requirements
owned by the reducer and later M03 packages and are **not** claimed here.

## 1. Accepted grammar (frozen)

Role tokens (case-insensitive, Vietnamese accents folded):

| Token | Action |
|---|---|
| XAY / XÂY / BUILD | `domain.RoleBuilder` |
| THU / THỦ / DEFEND | `domain.RoleGuard` |
| DANH / ĐÁNH / ATTACK | `domain.RoleFighter` |

Ballot tokens: `A`, `B`, `C` (case-insensitive) → `domain.VoteOptionA/B/C`, a
distinct `KindBallot` action, never a role. The parser does not decide wave parity,
membership, scheduled-tick legality or cooldown; those stay in the simulation
acceptance path.

Exactly one token is required after normalization. Punctuation, prefixes,
substrings, embedded commands, multiple tokens and digits are rejected. There is no
prefix/substring matching and no punctuation stripping.

## 2. Normalization pipeline (fixed order, locale-independent)

1. Raw byte length: empty → `ErrEmpty`, >500 bytes → `ErrTooLong` (before any
   Unicode work).
2. UTF-8 validity → `ErrInvalidUTF8`.
3. Forbidden-character scan (before and after NFKC): controls are rejected except
   legitimate whitespace controls (`\t \n \v \f \r` and Unicode Zs/Zl/Zp spaces);
   all Unicode format characters (bidi overrides/isolates, zero-width marks, BOM)
   are rejected; a leading combining mark is malformed; more than 8 combining marks
   is `ErrExcessiveCombining`.
4. NFKC compatibility normalization (`golang.org/x/text/unicode/norm`).
5. `strings.ToLower` (Unicode default case mapping, no locale).
6. Vietnamese fold: NFD decomposition, drop combining marks (Mn), map `đ`/`Đ` to
   `d`. Ordinary mark removal cannot handle `đ`, hence the explicit mapping.
7. Whitespace normalized to ASCII space, then trimmed.
8. Any remaining whitespace (multi-token) or non-allowlisted token →
   `ErrNotACommand`.
9. Exact allowlist lookup maps to the existing domain enums.

A pure-ASCII fast path skips NFKC/NFD because they are identity maps there; the
allowlist, one-token and size rules are identical on both paths.

## 3. Security properties

- `MaxCommentBytes = 500`, enforced first; a 501-byte comment costs ~1.5 ns and no
  allocation for the length check.
- Invalid UTF-8 is never normalized and cannot be laundered into a command.
- Bidi controls (U+202A–E, U+2066–9, U+200E/F, U+061C), zero-width characters
  (U+200B–D, U+2060, U+FEFF) and other format characters are rejected.
- Controls except legitimate whitespace are rejected, including NUL, BEL and NEL.
- Mixed-script lookalikes (Cyrillic `ХАУ`, Greek `Α`, mixed `ΑΤΤΑCΚ`) are rejected;
  there is no general confusable transliteration.
- NFKC-equivalent Latin/compatibility forms that normalize exactly to an authorized
  token are accepted (full-width `ＡＴＴＡＣＫ`, math bold `𝐁𝐔𝐈𝐋𝐃`, Roman
  numeral `ⅩAY`); compatibility characters that map to non-commands (`ﬁ`, `①`,
  `㎡`) are rejected.
- 500-byte, 42-case negative fixture proves rejection categories are stable.
- No logging, no raw input in errors, no identity, no network, no database, no
  locale, no randomness, no global mutable state; errors expose only sentinel
  categories and never echo the comment.
- No regex, no recursion, no unbounded allocation: the 500-byte cap bounds all
  normalization buffers.

## 4. Public API

```go
type Kind uint8           // KindNone, KindRole, KindBallot
type Action struct { Kind Kind; Role domain.Role; Ballot domain.VoteOption }
func (a Action) Valid() bool
func (a Action) IsRole() bool
func (a Action) IsBallot() bool
func ParseComment(raw string) (Action, error)
```

Errors: `ErrEmpty`, `ErrTooLong`, `ErrInvalidUTF8`, `ErrForbiddenCharacter`,
`ErrExcessiveCombining`, `ErrNotACommand` — all `errors.Is`-testable. A rejection
always returns the zero `Action`.

## 6. Test matrix (all executed)

Files: `parser_test.go`, `normalize_test.go`, `fuzz_test.go`,
`parser_bench_test.go`, `integration_test.go`, frozen
`testdata/grammar_fixtures.json`.

- Frozen fixture table: **28 positive** cases (all canonical commands, upper/lower/
  mixed case, precomposed and decomposed Vietnamese, whitespace variants, full-width
  NFKC forms, ballots) and **42 negative** cases (empty/whitespace, over-limit,
  invalid UTF-8, bidi/zero-width/controls, leading and excessive combining marks,
  mixed scripts, digits, punctuation, embedded/multi-token sentences, emoji,
  lookalikes). Each negative asserts the exact sentinel and the zero action.
- 20 unit test functions covering folding, whitespace, NFKC, spoofing, control
  policy, UTF-8, combining marks, digits, locale independence, action semantics,
  error taxonomy, size boundary, idempotence, enum/type compatibility, rejection
  non-usability and concurrent purity.
- Idempotence: every accepted token normalizes to itself; variants normalize to the
  token and re-normalize unchanged.
- Cross-platform: the fixture file stores exact UTF-8 bytes (`raw_hex`) and expected
  tokens/actions/errors; it is executed unchanged on Windows (local) and Linux (CI),
  so identical results are asserted rather than assumed.

## 9. Integration boundary

`integration_test.go` proves parsed roles equal the existing `domain.RoleBuilder`,
`RoleGuard`, `RoleFighter` values and ballots equal `domain.VoteOptionA/B/C`, and
that each value is directly usable in the existing `simulation.RoleCommand` /
`simulation.VoteCommand` fields without conversion. Rejections return the zero
action, which can never produce a valid role or ballot. A concurrency test (32
goroutines) proves purity and thread safety. No identity, durable event, database or
wave state is fabricated or touched.
