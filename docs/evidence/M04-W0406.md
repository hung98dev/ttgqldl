# M04-W0406 — Privacy erasure and independent deletion ledger

Status: **IN_PROGRESS**, not PASS. The durable request/outbox/export/anonymized
checkpoint/SQL-erasure core, a real physical backup-before-erasure restore/reapply
rehearsal and a real v1/v2 HMAC alias rotation/erasure test are implemented. Cross-session
scope, the full 20-case restore defect matrix and production readiness integration remain
incomplete. No client-facing readiness is claimed.

## 1. Implemented

- `internal/privacy` encrypted append-only ledger:
  - AES-256-GCM records with unique nonces and associated data binding ledger ID, seq and
    predecessor hash;
  - HMAC-SHA256 chain key, append-only files `0600` in a `0700` directory, temp+fsync+rename;
  - tombstone-idempotent append, sequence/chain/decryption verification and
    verifier-produced `CoverageProof`; caller booleans alone cannot pass
    `AllowClientServing`.
- Transactional erasure request:
  - `privacy_tombstones` + `privacy_ledger_outbox` + `privacy_erase_requests` in one
    transaction;
  - immediate `players.hide_alias=true, alias=NULL`;
  - idempotent `(session_id, actor_ref_protected, scope)`.
- Outbox exporter:
  - reads unexported rows in seq order, appends encrypted ledger record, then updates
    `exported_at`/`ledger_ack_ref`; append is tombstone-idempotent, retry-safe; failures
    increment attempts/last_error and do not claim success.
- Anonymized privacy boundary in `reducer.Anonymize`:
  - fenced W0401 transaction; removes erased actors from Members/Pending/XP/Ballots and
    pending role/ballot queues, removes their queued-next metadata;
  - increments privacy epoch exactly once, recomputes canonical v2 hash, writes a
    `privacy` journal operation and a new checkpoint;
  - retires older checkpoints so replay cannot select a pre-erasure checkpoint;
  - deletes aliases/players/session progress/wave members/ballots/input receipts/inputs
    for the erased actor(s) in the same fenced transaction.
- Migration 00009 adds idempotency scope, checkpoint privacy_epoch and the `privacy`
  journal operation.

## 3. Real physical backup-before-erasure restore

`TestRealPITRBackupBeforeErasureReapply` (real PostgreSQL 18.6 + Docker + encrypted
physical base backup):

1. Creates a village/session/player with v1+v2 HMAC aliases, session XP and input, then
   commits reducer revision R.
2. Creates a real encrypted physical base backup BEFORE erasure.
3. Requests/exports erasure to the independent encrypted ledger and applies the
   anonymized privacy checkpoint on the primary.
4. Deletes the primary container and PGDATA volume; backup/WAL volumes survive.
5. Restores the old backup to a target before erasure: the isolated restored cluster
   still contains the old player and both v1/v2 aliases (pre-erasure state).
6. Reapplies the deletion ledger by re-running the fenced anonymization on the restored
   cluster.
7. Verifies player/aliases = 0, W0403 replay passes, and the ledger coverage proof
   accepts the tombstone.
8. Test duration ~34 s.

`TestAliasRotationResolvesSamePlayerAndErasureRemovesAllVersions` proves v1 and v2
candidate aliases resolve to the same player and erasure removes both.

## 4. W0406-FIX defect remediation

### Request/tombstone ownership

Migration 00010 adds `privacy_erase_requests.tombstone_id` with a unique partial index and
an explicit FK. `Service.Apply` now joins `r.tombstone_id` to the outbox; it no longer
infers ownership from matching actor/scope strings. `TestErasureCannotBorrowAnotherRequestsAck`
proves an unexported request cannot use another session's acknowledged tombstone.

### Atomic completion

`Reducer.AnonymizeWithCompletion` runs a completion callback inside the same fenced
transaction after the checkpoint/journal/SQL-erasure writes. `Service.Apply` marks the
request `applied` and the tombstone `restore_applied_at` in that callback. Completion
failure rolls back the anonymization (`TestPrivacyCompletionFailureRollsBackAnonymization`).
No separate status transaction can diverge from the authoritative erasure.

### Ledger witness and readiness bypass

`Ledger` now writes an independent durable `head.witness` (fsync+rename+directory sync)
after every append. `Verify` reads the witness and refuses a missing/mismatched head;
`CoverageProof` binds `WitnessSeq`/`WitnessHash` and coverage time from the witness, not a
caller timestamp. The legacy boolean-only `pitr.PrivacyGate.AllowClientServing` was
removed; only `AllowClientServingWithLedgerProof` accepting a verifier-produced proof
remains. Witness/tamper/rollback tests fail closed.

### Automatic ledger-driven restore

`privacy.RestoreCoordinator` reads authenticated encrypted deletion payloads from the
independent ledger, discovers the session/actor, acquires writer authority, applies missing
anonymization boundaries, materializes the tombstone, records a durable restore run and
repeats idempotently. The physical PITR test no longer passes actor IDs manually:
`TestRealPITRBackupBeforeErasureReapply` restores the old backup, runs the coordinator,
verifies player/aliases are removed, ledger coverage passes, W0403 replay passes, and a
second coordinator run applies zero additional erasures.

### Wave boundary

`Reducer.Anonymize` rejects mid-wave ticks; only tick 0, 2800 and 3000 boundaries are
accepted (`TestPrivacyErasureRejectsMidWaveBoundary`). Queued requests remain queued and
suppressed until a safe boundary.

### HMAC rotation

The real rotation test now covers v1→v2→v3 aliases resolving to one player and erasure
removing all three.

  restore defect matrix.

- No external ledger replication/site-loss proof; local append-only directory only.

## 6. Security limitations

- Ledger keys are test-generated and file-local; production KMS/external key custody and
  independent replication are not implemented.
- Unkeyed SQL/backup hashes are not authentication; the ledger uses HMAC but a fully
  compromised host with keys can rewrite history. Trust anchor is the external key.
- No legal/GDPR compliance claim.
