# M04-W0406 — Privacy erasure and independent deletion ledger

Status: **IN_PROGRESS**, not PASS. The durable request/outbox/export/anonymized
checkpoint/SQL-erasure core is implemented and tested, but the mandatory real physical
backup-before-erasure / restore-after-erasure rehearsal and full HMAC-rotation database
campaign are not complete. No client-facing readiness is claimed.

## 1. Implemented

- `internal/privacy` encrypted append-only ledger:
  - AES-256-GCM records with unique nonces and associated data binding ledger ID, seq and
    predecessor hash;
  - HMAC-SHA256 chain key, append-only files `0600` in a `0700` directory, temp+fsync+rename;
  - tombstone-idempotent append, sequence/chain/decryption verification and
    verifier-produced `CoverageProof`; caller booleans alone cannot pass
    `AllowClientServing`.
- Transactional erasure request:
  - `privacy_tombstones` + `privacy_ledger_outbox` + `privacy_erase_requests` in one
    transaction;
  - immediate `players.hide_alias=true, alias=NULL`;
  - idempotent `(session_id, actor_ref_protected, scope)`.
- Outbox exporter:
  - reads unexported rows in seq order, appends encrypted ledger record, then updates
    `exported_at`/`ledger_ack_ref`; append is tombstone-idempotent, retry-safe; failures
    increment attempts/last_error and do not claim success.
- Anonymized privacy boundary in `reducer.Anonymize`:
  - fenced W0401 transaction; removes erased actors from Members/Pending/XP/Ballots and
    pending role/ballot queues, removes their queued-next metadata;
  - increments privacy epoch exactly once, recomputes canonical v2 hash, writes a
    `privacy` journal operation and a new checkpoint;
  - retires older checkpoints so replay cannot select a pre-erasure checkpoint;
  - deletes aliases/players/session progress/wave members/ballots/input receipts/inputs
    for the erased actor(s) in the same fenced transaction.
- Migration 00009 adds idempotency scope, checkpoint privacy_epoch and the `privacy`
  journal operation.

## 2. Real PostgreSQL evidence

  checkpoint;

- `Apply` then commits anonymized checkpoint, privacy epoch=1, removes alias/player/
  progress/member/input rows, and W0403 replay passes;
- ledger tamper/wrong-key/sequence-gap tests fail closed;
- six-point retention and missing external ledger gates fail closed.

`TestPrivacyAnonymizeRemovesActorAndRetiresOldCheckpoints` verifies old checkpoint
retirement and complete private-state removal.

## 3. Not completed (why IN_PROGRESS)

- No real W0405 physical backup-before-erasure → destroy PGDATA → restore old backup →
  replay external ledger → verify no resurrection rehearsal.
- No full HMAC v1/v2/v3 rotation plus erasure database campaign; only the existing
  identity package rotation tests and a single alias erasure path.
- No integration of the verified ledger proof into the W0405 restore gate/API readiness;
  the new `privacy.AllowClientServing` proof exists but the PITR harness still uses the
  old fail-closed boolean gate.
- No real 20-case restore defect matrix, cross-session/cross-village erasure, or
  concurrent key-rotation/erasure campaign.
- No external ledger replication/site-loss proof; local append-only directory only.
- No client-facing readiness endpoint; M05/M07 boundaries remain unimplemented.

## 4. Security limitations

- Ledger keys are test-generated and file-local; production KMS/external key custody and
  independent replication are not implemented.
- Unkeyed SQL/backup hashes are not authentication; the ledger uses HMAC but a fully
  compromised host with keys can rewrite history. Trust anchor is the external key.
- No legal/GDPR compliance claim.
