# M01-W0101 — Go backend bootstrap (Phase A scope)

## Deliverable
A real, modular Go backend module with a strict dependency direction, structured
logging, context-aware lifecycle and the documented liveness/readiness contract.
No gameplay, authentication, source adapter or unfinished placeholder API is
implemented.

## Structure created
```
backend/
  go.mod (module github.com/hung98dev/ttgqldl/backend, go 1.27.3)
  go.sum
  cmd/server/main.go            config load → logger → pool → app → signals
  internal/app/                 HTTP server, middleware, health/ready handlers
  internal/config/              typed register + .env parser
  internal/storage/             pgx/v5 pool, lazy connect, Ping, ServerVersion
  internal/telemetry/           log/slog JSON logger
  internal/domain|simulation|commands|source|identity|stream|operator/  doc.go only
  db/migrations|queries/        README only — W0103 owns the schema
  test/integration/             real PostgreSQL / unreachable-server tests
  test/golden|load/             README only — M02 / M08 own them
```
Dependency direction: `cmd → app/storage/config/telemetry`; `app` knows only
`Check{Name, Run func(ctx) error}` and `WriterEpoch func() int64`; `storage`
never imports `app`; the future domain packages import nothing infrastructural.
There are no cycles (`go vet ./...` and the build prove it).

## HTTP contract implemented
| Route | Behaviour |
|---|---|
| `GET /healthz` | 200 `{"status":"alive"}`; performs no dependency I/O |
| `GET /readyz` | 200 `{"status":"ready","writer_epoch":N}` when every check passes; 503 with the documented error envelope `{"error":{"code":"UNAVAILABLE","message":"readiness failed: postgres","request_id":"<uuid>","retryable":true}}` otherwise |
| other paths | 404 `NOT_FOUND` envelope |
| wrong method on a known path | 405 `METHOD_NOT_ALLOWED` + `Allow: GET, HEAD` |

`writer_epoch` is `0` because no simulation writer lease exists before M04; the
value is truthful (no lease), not a placeholder success.

Middleware: request id (reuses a well-formed `X-Request-Id`, replaces oversized
or control-character values), structured access log, panic recovery to a 500
`INTERNAL` envelope, bounded response bodies. Server timeouts:
`ReadHeaderTimeout=5s`, `ReadTimeout=10s`, `WriteTimeout=15s`, `IdleTimeout=60s`.

## Lifecycle
`signal.NotifyContext(os.Interrupt, syscall.SIGTERM)` → graceful `Shutdown`
bounded by `TTG_SHUTDOWN_TIMEOUT`; `Serve` returns `nil` for a requested stop and
a wrapped error for a real failure, so a supervisor can distinguish them.

## Runtime proof
```
$ ./backend-run.ps1  (server started against the compose database)
$ curl -s -w '%{http_code}' http://127.0.0.1:8080/healthz
{"status":"alive"} 200
$ curl -s -w '%{http_code}' http://127.0.0.1:8080/readyz
{"status":"ready","writer_epoch":0} 200
```
With the database container stopped (`./dev-down.ps1`):
```
$ curl -s -w '%{http_code}' http://127.0.0.1:8080/healthz
{"status":"alive"} 200
$ curl -s -w '%{http_code}' http://127.0.0.1:8080/readyz
{"error":{"code":"UNAVAILABLE","message":"readiness failed: postgres","request_id":"5c4fa127-9510-4ec5-8dc0-d85291dfbb20","retryable":true}} 503
```
After `./dev-up.ps1` the same process returns `200 {"status":"ready"...}` again
(the pool reconnects lazily; no restart required).

## Tests added
`internal/config`: defaults, explicit values, 19 invalid-value cases, stage/prod
secret requirements, TLS refusal for remote plaintext, multi-error reporting,
nil `getenv`. `internal/config`: dotenv parsing/quoting/malformed lines/apply
without overriding the process environment. `internal/app`: option validation,
health (and proof that liveness does not run checks), readiness success/epoch,
failing dependency, timeout enforcement, panicking check, 404/405/HEAD, panic
recovery, request-id sanitisation, graceful shutdown, already-cancelled context,
bind failure. `internal/storage`: empty/malformed DSN, lazy open, unreachable
ping, nil pool safety, pool stats. `test/integration`: readiness fails with an
unreachable server and the real PostgreSQL test.

## Honest limits
- QA-API-01 is **not** satisfied: there is no OpenAPI 3.1 document and the full
  route set does not exist yet. Only the health/readiness contract is exercised;
  M05 owns the contract tests.
- `go test -race` cannot run on this Windows host (`go: -race requires cgo`); the
  race gate was executed on Linux in `golang:1.27.3` and is also run by CI.
- `cmd/server` has no unit test (thin wiring); its behaviour is covered through
  the app, integration and runtime probes above.
- No SQL, gameplay, auth, source adapter or WebSocket code exists.
