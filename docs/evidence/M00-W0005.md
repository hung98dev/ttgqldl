# M00-W0005 — Requirement-to-test traceability

## Deliverable
`docs/traceability.csv` with the canonical header

```
requirement_id,document_anchor,owner_module,work_package,test_id,priority,verification_method,spec_status,impl_status,evidence_uri
```

and 74 normative requirement rows covering every module 01–11. Every one of the 63 QA ids defined in 09_QA_ACCEPTANCE.md is referenced by at least one row; the validator fails if any QA id is unmapped.

## What each column means
- `requirement_id`: stable slug minted for this baseline (`REQ-<module>-<topic>`); it identifies a normative clause cluster, not a new plan.
- `document_anchor`: `<module>.md#<github-heading-slug>`; the validator recomputes heading slugs and fails if the anchor does not resolve, so a row cannot point at a heading that was renamed or deleted.
- `owner_module`: the module that owns the requirement (00_INDEX.md ownership map).
- `work_package`: must exist in the implementation matrix; the validator cross-checks the `W…` to `M…` prefix.
- `test_id`: semicolon-separated QA ids, accepting the `QA-X-06..09` and `QA-GOV-01/02/03` shorthands used elsewhere in the plan.
- `priority`: P0 / P1.
- `verification_method`: AUTOMATED, MANUAL, AUTOMATED+MANUAL or STATIC.
- `spec_status`: VERIFIED (reviewed and consistent), FIXED (a defect found in M00 was corrected in the owning module), BLOCKED (needs external evidence).
- `impl_status`: the matrix vocabulary. **Every implementation status is NOT_STARTED or BLOCKED here — no implementation claim is made.**
- `evidence_uri`: a repository path that must exist and that documents the current status.

## Distribution
- P0 rows: the large majority; P1 rows cover retention, observability trade-offs, visual performance, known-issue mitigation, Unity legibility and WS snapshot projection.
- `spec_status`: VERIFIED / FIXED / BLOCKED split reflects exactly the round-2 findings — BLOCKED rows are the external gates, privacy restore and manual performance/UX evidence.
- `impl_status`: nothing is PASS. The 6 rows that are BLOCKED are blocked on external evidence (live permission, legal, human UX, restore drill), not on code.

## Static checks that back this package
The validator enforces, for each row: resolvable anchor, defined work package, defined QA ids, valid priority/method/status vocabulary, and an existing evidence file. It also fails if a QA id defined in 09 is never mapped, or if two rows share a requirement id.
