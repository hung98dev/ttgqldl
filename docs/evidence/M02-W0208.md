# M02-W0208 - Golden fixtures, canonical hash and deterministic replay

Implemented scope: production-reducer golden boss vectors P=10 and P=30, canonical
RFC 8785 projection and SHA-256 state hash, and a 110-position checkpoint/restart
replay harness. **Status is IN_PROGRESS** because the QA-BAL-05 fighter-share
curve and the broader golden matrix are not yet executed.

## Golden vectors (production reducer, synthetic wave-5 fixture)

Fixture: fresh village, 10/30 roles joined at tick 0, wave 5, no vote. This is an
explicitly documented mathematical fixture, not a recorded playthrough.

| Population | base_hp | boss_max | boss HP at 2600 | boss HP at 2800 | result | wall | wood | stone | food | session XP |
|---|---|---|---|---|---|---|---|---|---|---|
| 10 (2B/2G/6F) | 162 | 33 | 0 (killed) | 0 | victory | 1000 | 518 | 324 | 350 | 100 |
| 30 (8B/8G/14F) | 238 | 48 | 16 | 0 | victory | 1000 | 544 | 338 | 350 | 300 |

Both match the binding expected values exactly; the P=30 case fails if the
tick-2800 final combat is skipped (boss would survive with 16 HP), which the test
detects.

## Canonical state and hash

`backend/internal/canonical`:
- `Project` builds the versioned documented field set (schema/rules versions,
  session/village ids, wave/tick/lifecycle/defeated, village resources and
  progression, anchor/difficulty/base_hp, lane pools, boss, vote with ballots,
  members with `session_xp`/`xp_awarded`/nullable `last_change_tick`, queued next
  wave, privacy epoch);
- `MarshalJCS` emits RFC 8785 canonical JSON: sorted keys, no whitespace, no
  floats (unsupported types rejected), explicit nulls, int64 decimal strings;
- `Hash` returns the hex SHA-256 of those bytes.

Tests: JCS known vectors (key ordering, arrays, null/bool, large int64, escaping),
determinism, unsorted-member rejection, foreign rules/schema rejection,
nullable-field explicitness, and sensitivity to wood/wall/role/`xp_awarded`/
session XP/privacy epoch/change tick.

## Replay

`replay_017_test.go` runs uninterrupted traces and reconstructs 110 checkpoint
positions by replaying the prefix from the initial fixture, then resuming with
deep-copied state and queue. Every subsequent canonical hash, the final state and
the event stream are compared. Corruption tests change resources or the rules
version and must fail hash verification.

## Phase A remediation in this task

- capped members now persist `xp_awarded` bookkeeping even though their XP cannot
  grow past 300 (`TestCappedXPStillPersistsBookkeeping`);
- `settleWave` independently enforces tick 2800, RESULTS phase and a running

  (`TestSettlementRejectsInvalidTiming`);

  both acceptance orders (`TestCrossKindInputSequenceUniqueness`);
- the completed `wave_result` supersedes the internal settlement marker, so the
  observable tick-2800 order is boundaries, final attack, `wave_result`,
  `phase_changed` (`TestFinalBoundaryEventSequence`).

### Private checkpoint integrity — implemented

`simulation/checkpoint.go` adds a versioned envelope covering the canonical state
hash **and** every queued role/ballot command (input seq, actor, role/option,
target wave, accepted and scheduled ticks). `VerifyCheckpointEnvelope` recomputes
the digest, rejects queue/state mismatches, duplicate sequences, invalid commands
and foreign rules versions. Tamper regressions cover role, schedule, ballot
option, removed command, integrity hash, queue mismatch and rules version.

### XP canonical contract — proposal, not approved

The canonical v1 member list only hashes `session_xp` for current-wave members,
so retained XP of a departed actor cannot be detected
(`TestPersistedXPOutsideCurrentMembersIsNotHashed` remains in place). Proposed
schema v2 adds `session_progress: [{actor_key, session_xp}]` sorted by ActorKey,
without changing `ttg-rules-v1`, gameplay or rewards. **Owner approval is
explicitly outstanding and has not been fabricated or self-granted**, so
`CanonicalSchemaVersion` remains 1.
