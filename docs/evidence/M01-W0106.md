## Hardening — Task 003 (database CI and action maintenance)

The first version of this workflow used a stock `postgres` service container and
applied migrations as that container's superuser. That verified SQL, but not the
least-privilege model that production depends on, and it left `docker/postgres/
initdb/001_roles.sh` untested in CI.

### What changed
- **PostgreSQL is now started by the job itself** with `docker run` from the same
  pinned digest as `compose.dev.yaml` and with `docker/postgres/initdb` mounted,
  so the real role bootstrap runs in CI. The container has the same health check
  (`pg_isready`, 5s/3s/20 retries/15s start period) and the job waits for
  `healthy` before continuing.
- **Separate roles throughout the job**: `ttg_owner` (non-superuser, CREATE on
  the database) runs `cmd/migrate`; `ttg_app` (row-level DML only) runs the
  integration suite, which now includes the role and DDL-denial assertions; the
  bootstrap superuser exists only to create the roles/database.
- **Credentials are generated per run** (`openssl rand -hex 16`), written to
  `GITHUB_ENV` and masked with `::add-mask::` before any step can print them.
  No credential appears in the workflow file or in logs.
- **New gates**: schema fingerprint drift and `sqlc diff` generated-code drift,
  plus the destructive migration lifecycle test on the disposable CI database.
- **Actions upgraded** after checking the published releases: `actions/checkout`
  v7.0.1 and `actions/setup-go` v7.0.0, both pinned to the verified immutable
  commit SHAs (`3d3c42e5…`, `b7ad1dad…`). `setup-go@v7` runs on the Node 24
  runtime, which removes the Node 20 deprecation warnings the previous run
  emitted and drops no cache features (`cache`, `cache-dependency-path` are
  still inputs in v7).

### Job steps (backend)
Checkout → Set up Go → generate credentials → start PostgreSQL with the initdb
bootstrap → gofmt → go vet → unit tests → race tests → migrations up as
`ttg_owner` → schema/permission/runtime tests as `ttg_app` → destructive
migration lifecycle → roll back to zero and re-apply → `sqlc diff` → linux
build → stop PostgreSQL (always).

### Known gaps that keep this package IN_PROGRESS
- Still missing from the 09 CI stage list: Unity EditMode/PlayMode, the
  TypeScript operator build, SAST/SBOM/secret/licence scanning, and the load
  harness. Those belong to W0104, W0105, M06 and M08.
- The workflow pins action SHAs manually; there is no Dependabot or automated
  refresh, so an action security release requires a manual bump.
- No branch protection or required-check configuration is managed from code.
