# M02-W0205 - Builder economy, wall repair/upgrade, combat and damage

Authoritative deterministic gameplay for the 200-tick resolution boundaries.
Pure Go, checked int64, no floating point, no randomness, no I/O. Votes (W0206),
settlement/rewards/XP (W0207) and replay fixtures (W0208) remain out of scope.

## Ordering implemented per boundary

`resolveContribution` then `resolveCombat`, invoked inside the winning tick in
`advanceTick` before any settlement signal:

1. eligible commands were already applied by `ApplyDueRoles`;
2. active role counts (`joined_tick <= t`, each role capped at 10,000);
3. XP hook reserved for W0207 (nothing awarded here);
4. builder wood/stone generation;
5. wall repair from newly generated wood;
6. at most one wall upgrade;
7. boss spawn at 2600 (W0204) before combat;
8. fighter + militia attack;
9. retaliation from post-attack surviving HP;
10. guard block;
11. wall then townhall damage;
12. immediate `Defeated` when townhall reaches zero.

Defeated waves skip economy and combat entirely, keep prior valid effects, and
still advance toward the tick-2800 settlement hook.

## Formulas verified

| Item | Formula implemented |
|---|---|
| wood gain | `2*isqrt(B) + floor(B/50)` |
| stone gain | `isqrt(B) + floor(B/500)` |
| resource cap | 1,000,000 each |
| repair capacity | `8*isqrt(B)` |
| repair | `min(capacity, wall_max-wall_hp, 5*wood)`; cost `ceil(repair/5)` |
| upgrade | `threshold = 200*tier`, `stone = 100*tier`, one per boundary, tier max 20, `+200 HP` capped to the new maximum |
| fighter attack | `18*isqrt(min(F,10000))` |
| militia | locked value from W0204 (system assistance) |
| attack split | `floor(A/3)` per lane, remainder cyclic from `combat_index % 3` |
| lane priority | runner → grunt → brute → center boss last |
| redistribution | cyclic over all living pools, `min(pool_hp, remaining)`, boss killable |
| retaliation | `raw = ceil(base_raw*ordinary_remaining/base_hp)` if ordinary remains, plus `ceil(base_raw/5)` if the boss lives; `base_raw = 10+3d+9*isqrt(P)` |
| guard block | `8*isqrt(min(G,10000))`; damage `max(0, raw-block)` |
| damage | wall first, then townhall, never negative, immediate defeat |

## Phase A repairs in this task

- wave start is authorized only from the accepted queue head: `AdvanceWithRoles`
  rejects an empty queue (`ErrNoRegistration`), a mismatched actor/role
  (`ErrStartMismatch`), consumes the command once and emits exactly one
  `role_accepted`; a replayed start is rejected;
- `RoleCommand` now separates acceptance position (`AcceptedTick`) from target
  wave and effective tick; a current-wave command accepted at 2799 applies at
  2800, while NEXT-wave commands are accepted only during RESULTS with effective
  tick 0 and never alter the finishing wave;
- premature next-wave registrations are rejected at ticks 100/800/1600/2799;
- rollover clears `BossIncoming` (per-wave flag);
- each pool is bounded by its immutable initial allocation and canonical identity,
  in addition to total conservation;
- the contradictory overflow test was replaced with real positive/negative
  assertions.
