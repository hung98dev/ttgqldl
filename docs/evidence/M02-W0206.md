# M02-W0206 - Deterministic voting, ballots, selection and combat modifiers

Even-wave voting implemented on the authoritative tick reducer. Pure Go, integer
arithmetic only, no separate vote clock, no I/O.

## Rules implemented

| Item | Behavior |
|---|---|
| Availability | `wave_no % 2 == 0` only |
| Opens | tick 800, once, selected NONE, `vote_opened` |
| Ballot window | effective ticks 800..1199 inclusive; 1200 is late |
| Eligible voter | current-wave member with `joined_tick <= ballot tick`; pending NEXT-wave actors cannot vote |
| Latest ballot wins | one stored ballot per actor; later effective tick wins; same tick decided by `input_seq` |
| Close | tick 1200, before that tick's builder economy |
| Selection | highest count, tie A > B > C, first affordable; zero ballots: A if wood >= 50 else C |
| Costs | A: 50 wood, B: 50 food, C: free; deducted exactly once at close |
| Modifiers | A: guard x115%; B: attack x115% before lane split; C: guard x90%; floors applied |
| Rollover | vote state and ballots reset |

## APIs

- `domain/vote.go`: `VoteAvailable`, `BallotTickEligible`, `VoteCost`,
  `VoteAffordable`, `VoteGuardPercent`, `VoteAttackPercent`, `ApplyVotePercent`,
  `LossPenaltyAfterC` (W0207 contract), `SelectVote`.
- `simulation/vote.go`: `VoteCommand`, `VoteDecision`, `AcceptVoteCommands`
  (atomic validation plus latest-per-actor upsert), `openVote`, `closeVote`,
  `VoteModifiers`, `VoteDeferredError` (paused truthfulness).
- `domain.Ballot` now carries `InputSeq`, and `VoteState` has `Closed`.
- Events: `vote_opened`, `vote_closed` (aggregate selection only, no actor keys).

## Numerical checks

| Case | Result |
|---|---|
| A=5,B=5,C=2, wood >= 50 | A (tie priority) |
| A=10,B=7,C=1, wood 20/food 80 | B |
| A=10,B=7,C=1, wood 20/food 30 | C |
| no ballots, wood 80 | A, wood -50 |
| no ballots, wood 20 | C, no charge |
| guard base 8 | A -> 9, C -> 7, none -> 8 |
| attack 58 with B | 66 (floor) |
| loss penalty 101 with C | 50 |
