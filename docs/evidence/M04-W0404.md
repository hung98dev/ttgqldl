# M04-W0404 — SQL crash restart, writer takeover and authoritative recovery

Status: **PASS** for W0404's process-crash/recovery boundary. M04 remains IN_PROGRESS;
W0405–W0407 are NOT_STARTED. This is not PITR/backup restore, privacy-erasure recovery or
M08 recovery-time acceptance.

## 1. W0403 replay audit and repairs

Two real replay gaps were found before recovery acceptance:

### A. Repeated `accepted_tick` across waves

W0403 grouped history only by `AcceptedTick`; wave-1 tick800 and wave-2 tick800 were
indistinguishable. Migration `00008_replay_wave_boundary.sql` adds
`input_events.accepted_wave` (written by W0305 from the committed session wave) and the
replay key is now `(accepted_wave, accepted_tick)`. Historical rows with NULL
`accepted_wave` fail closed. Regression
`TestReplaySelectionSeparatesRepeatedWaveTicks` proves wave-2 tick800 selects only the
wave-2 event.

### B. Later input influencing an earlier target revision

W0403 read the whole session input log. Migration 00008 adds
`reducer_transitions.input_seq_high`; each journal row records the exact input-sequence
horizon visible to that committed transition. Replay filters selected inputs by
`input_seq <= journal.input_seq_high`, so an input appended at the same tick after an
earlier revision cannot influence replay to that earlier revision. Regression
`TestHistoricalTargetExcludesLaterInputAtSameTick` replays revision2 and revision3 with a
later same-tick input and gets distinct, correct hashes. Replay also restores
`state.InputSequence` from the journal horizon, which fixed a private-continuation
mismatch found by that test.

## 2. Recovery architecture

New `backend/internal/recovery`:

- `Coordinator.Recover`: acquires a fresh W0401 lease, verifies session/village/rules,
  handles pristine WAITING, runs W0403 `VerifyReplay`, renews/revalidates the lease, then
  re-reads revision/tick/hash and enters `READY` only when all values match.
- States: `UNINITIALIZED`, `ACQUIRING_LEASE`, `VERIFYING_HISTORY`, `READY`,
  `INTEGRITY_FAILED`, `STOPPED`.
- `Coordinator.Step` runs the W0402 fenced transition using the verified lease.
- Integrity failure releases ownership and never falls back to an older checkpoint or
  starts a new game.
- The coordinator is an executable recovery boundary; the M01 HTTP skeleton remains
  health/readiness-only and is not claimed as a production gameplay server.

## 3. Actual process crash tests

`TestRealProcessKillRecoveryAfterCommit`:

- Parent creates a real PostgreSQL session and first-join input.
- Child A (independent `go test` process) acquires the lease, commits the first join plus
  three quiet ticks, prints the committed revision/tick/hash and blocks.
- Parent kills Child A without graceful release. PostgreSQL keeps the committed state and
  the abandoned lease.
- Parent waits for PostgreSQL lease expiry, then starts Child B with fresh memory.
- Child B acquires epoch+1, verifies checkpoint/journal/replay, recovers the exact
  revision/tick/hash, commits one more fenced tick and releases.
- Assertions: same pre-crash revision/hash, next revision/tick, no outbox count change,
  no duplicate transition.

`TestRealProcessKillBeforeTransaction`:

- Child A acquires the lease and blocks before any Step; parent kills it.
- Child B takes over, recovers pristine WAITING and starts wave 1 at tick0 exactly once.

Both tests ran on Windows (`Process.Kill`) and in the Linux Go 1.27.3 container where the
child receives SIGKILL. **Actual child-process kills: 2** (one post-commit, one
pre-transaction). No in-process error was mislabeled as SIGKILL.

## 4. Deterministic recovery campaign

`TestHundredAbandonedLeaseRecoveryPositions` runs **100 distinct committed revisions**:
each iteration abandons the previous lease without release, waits for PostgreSQL-authoritative
200 ms expiry, takes over with a new epoch, verifies checkpoint/replay and commits one
fenced transition. Result: revisions 1..100, zero recovery/replay mismatches, zero
duplicate effects. This is a deterministic crash-like lease-takeover campaign; it is not
counted as 100 additional SIGKILLs.

`TestCoordinatorRecoversPristineAndCommittedState` verifies pristine start, committed
recovery and continued tick. `TestCoordinatorRejectsCorruptCheckpoint` verifies corruption
fails closed.

## 5. Atomicity, stale writer and outbox

- W0402 failure injection (13 stages including checkpoint insertion) proves no partial

- W0401 takeover proof: old epoch cannot renew/release/fence; new epoch owns the session.
- Process Child B acquires epoch+1 after expiry; old child is dead and its in-memory lease
