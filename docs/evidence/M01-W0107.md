# M01-W0107 — Initial development tooling and environment verification (Phase A)

## Deliverable
Portable entry points in `tooling/`, each in PowerShell and Bash, that resolve
the repository root themselves, propagate exit codes and never destroy data by
default. Phase A scope; the remaining commands in the 08 register
(`migrate-*`, `test-integration`, `test-golden`, `test-load`, `test-unity`,
`test-operator`, `test-security`, `backup`, `restore-verify`, `capture-obs`)
belong to later milestones.

| Script pair | Behaviour |
|---|---|
| `doctor` | one row per dependency with status `OK` / `MISSING` / `MISMATCH` / `BLOCKED`; required = Go 1.27.3 (effective in `backend/`), Docker + Compose plugin, pinned PostgreSQL image digest, ≥5 GiB free disk; optional = Node (W0105), Unity (M06), `.env`. `-Strict` also fails on optional gaps |
| `dev-up` | creates `.env` from `.env.example` when absent, then `docker compose up -d --wait`; never edits an existing `.env` |
| `dev-down` | `docker compose down` without `--volumes`; `-WipeData` requires an interactive confirmation |
| `backend-run` | sets `TTG_ENV_FILE` to the repository `.env`, runs `go run ./cmd/server` |
| `backend-test` | gofmt check, `go vet`, `go test`; `-Race` adds `go test -race`; `-Short` supported |
| `tooling-test` | tooling `go vet` + `go test`, plan validator, golden vectors |

Shared helpers (`_common.ps1|.sh`) provide root resolution, logging, the
pinned-toolchain override (announced, process-scoped) and `Invoke-Go`, which
returns **only** the exit code so callers cannot capture command output by
accident.

## Toolchain handling
The host Go env file pins `GOTOOLCHAIN=go1.27.1` while `backend/go.mod` requires
`go 1.27.3`. The scripts pass `GOTOOLCHAIN=auto` **to their own Go invocations**
and print:
`[go] GOTOOLCHAIN 'go1.27.1' overridden to 'auto' for this command so backend/go.mod can select go1.27.3`.
They never edit `go env`; the permanent fix is documented as
`go env -w GOTOOLCHAIN=auto`.

## Honest limits
- The Phase A scripts do not yet provide `migrate-*`, `test-*`, `backup`,
  `restore-verify` or `capture-obs`; `dev-up`/`dev-down` are the concrete names
  for the plan's `up`/`down` until the operator and mock-source services join
  the compose file (recorded in 08_OPERATIONS.md).
- The Bash scripts were syntax-checked on all files and executed for
  `doctor.sh` and `backend-test.sh` under Git Bash; `dev-up.sh`/`dev-down.sh`
  were not executed on this host (the PowerShell pair was). CI runs `bash -n`
  on every script; full Bash execution belongs to the Linux CI job.
- `doctor` cannot validate a Unity licence; that requires launching the editor
  under M06 and is explicitly out of scope here.
