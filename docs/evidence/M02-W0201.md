# M02-W0201 - Deterministic game domain, types, initial state and integer primitives

Foundation package for the authoritative simulation: pure Go, no I/O, no clock,
no randomness, signed int64 with checked arithmetic. It deliberately does not
implement combat, votes, settlement, rollover processing, persistence or replay;
those are W0202-W0208.

## Identity and geometry

| Item | Value |
|---|---|
| Rules identifier | `ttg-rules-v1` (unchanged) |
| Canonical schema version | 1 |
| Tick rate | 10 Hz |
| Wave length | 3000 ticks (300 s) |
| WAITING tick | -1 |
| Gameplay ticks | 0..2999 |
| Rollover tick | 3000, control transition only |
| Phase bounds | prep [0,1600), assault [1600,2600), finale [2600,2800), results [2800,3000) |

## Initial-state contract (deterministic)

| Field | Initial value |
|---|---|
| Village level / wall tier | 1 / 1 |
| Wall HP | 1000 (`WallMax(1) = 1000 + 200*(tier-1)`) |
| Townhall HP | 500 |
| Wood / stone / food | 400 / 250 / 300 |
| Construction work | 0 |
| Total wins | 0 |
| Consecutive wins / losses | 0 / 0 |
| Wave number / wave tick | 1 / -1 |
| Lifecycle | waiting |
| Members, pending members, XP, ballots, pools, boss | empty; no fabricated participants |
| Difficulty | level 1, population anchor 0 |

NewInitialState(villageID, sessionID, mode) validates both UUIDs and the source
mode, generates nothing (no UUID, no clock), and validates the produced state
before returning it. Identical inputs produce a deep-equal state.

## Invariants enforced

Village: level 1..50, wall tier 1..20, `wall_hp <= WallMax(tier)`, townhall
0..500, each resource 0..1,000,000, non-negative work and wins.

Wave: number >= 1, tick -1..3000, phase exactly matching the derived phase (tick
3000 must be results), non-negative pool HP, canonical pool order with no
duplicates, no boss archetype in ordinary pools, boss only on waves divisible by
five at or after tick 2600 with `0 < hp <= max`, no boss HP while absent, vote
counters non-negative and a closed vote may carry a selection, ballots unique by
actor with a valid option and no future tick, defeat only in finale/results,
result only in results, defeat result requires the defeated flag.

Session: valid revision, UUID identities that agree with the village, valid
source mode and lifecycle, pause reasons unique and consistent with the lifecycle,
members unique/sorted with joined tick 0..2999 and role-change ticks inside the
wave, pending members unique with a future target wave, XP unique and 0..300,
consecutive wins 0..10, losses 0..3, difficulty 1..10, non-negative anchor,
privacy epoch and input sequence.

Validation never repairs state: it returns every broken invariant.

## Reference evaluator compatibility

Constants were cross-checked against the independent oracle
`tooling/refeval` (rules version, 10 Hz, 3000 ticks, phase bounds, 1000+200*(tier-1)
wall maximum, 500 townhall, 300 XP cap, 10 XP per wave, 20 tiers, 50 levels, 600
tick role cooldown, vote close 1200, population lock 1600, boss spawn 2600,
final combat 2800). The evaluator was not modified and is not imported by
production code.

## Limitations

- No state transition, reducer, event emission, hashing or persistence yet.
- Population anchor semantics are represented but only enforced structurally.
- `ValidationError.MarshalJSON` is a diagnostic convenience, not the canonical
  hash serialization.

## Remediation (source review, 2026-11-04)

A source-level review found six correctness defects that the original tests did
not detect. All are fixed and covered by regression tests that fail on the old
implementation.

| # | Defect | Fix | Regression test |
|---|---|---|---|
| 1 | `SafeRatio` divided by `scale` before checking `scale != 0`, so a zero scale panicked | zero checks precede all division; the fast-path bound is only evaluated for a positive scale | `TestSafeRatioZeroScaleDoesNotPanic`, `TestSafeRatioZeroDenominatorIsAnErrorNotAPanic` |
| 2 | Large products reported false overflow (e.g. `SafePercent(MaxInt64-1, MaxInt64)`) | exact `floor(num*scale/den)`: int64 fast path when the product fits, otherwise `math/big` with an int64 range check | `TestSafePercentNearMaximumIsExact`, `TestSafeRatioMatchesBigIntOracle`, `FuzzSafeRatioNoPanic` |
| 3 | `defeated` was rejected outside FINALE/RESULTS, making legitimate losses at tick 1800 impossible to represent | defeat is valid from the first combat boundary (tick >= 1800) in ASSAULT, FINALE or RESULTS; PREP defeat is still rejected | `TestDefeatIsValidFromFirstCombatBoundary`, `TestDefeatDuringPrepOrBeforeCombatIsRejected` |
| 4 | `WaveResultDefeat` required `defeated == true`, conflating "town hall fell" with "wave lost at settlement" | loss is valid with or without defeat; victory still cannot coexist with defeat; result is still only allowed in RESULTS | `TestLossVersusDefeat` |
| 5 | A spawned boss had to have `HP > 0`, so a killed boss could not be represented | `Exists` records the spawn and is independent of `HP`; dead boss keeps `Exists=true`, `HP=0` until rollover; negative or above-maximum HP is still rejected | `TestBossLifecycleStates` |
| 6 | `WaveMember` lacked `first_switch_used` and used `-1` instead of a nullable `last_change_tick`; pending registrations could target any distant wave | nullable `LastChangeTick *int` plus `FirstSwitchUsed`, with both directions of the invariant enforced; pending target must be exactly current+1 | `TestWaveMemberFirstSwitchSemantics`, `TestPendingTargetMustBeExactlyNextWave` |

Additional hardening from the same review: ballots must fall inside the voting
window `[0,1200)`, an open vote cannot outlive the close tick, `source_disconnected`
and `storage_unavailable` lifecycles require their matching pause reason, a
stopped session may not carry pause reasons, the population anchor is bounded by
the documented 10,000 cap, and a zero-value state is rejected.

`Clone` was also corrected to preserve the difference between a nil and an empty
canonical collection, so a cloned state serialises identically to its source.

Post-remediation status: **PASS** (W0202 was implemented on top of this corrected
model).
