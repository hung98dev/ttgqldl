# M01-W0105 — React/TypeScript operator foundation

A real, buildable, tested operator console in `operator/`. It talks to the two
endpoints that actually exist (`GET /healthz`, `GET /readyz`) and refuses to
pretend that the rest of M05/M07 exists.

## 3. API integration — only what exists

| Endpoint | State | Behaviour |
|---|---|---|
| `GET /healthz` | AVAILABLE | parsed as `{status:"alive"}`; retried twice on transient failure |
| `GET /readyz` | AVAILABLE | 200 → `{status:"ready",writer_epoch}`; **503 is a normal degraded answer** carrying the backend reason, not a transport error |
| `/admin/v1/*` | UNAVAILABLE | contracts defined, never called; every action disabled with its owning milestone |

Client properties: configurable base URL, 4 s timeout per attempt, one
`AbortController` per attempt composed with the caller signal, `credentials:
'include'` for the future HttpOnly cookie + CSRF flow, bounded retries only for
idempotent reads, and safe error conversion into a single `ApiError`
(`kind` = http/network/timeout/protocol/aborted). Nothing logs credentials or
response bodies.

Capability matrix (`api/capabilities.ts`) is the single source of truth:
2 AVAILABLE, 9 UNAVAILABLE (M04/M05/M07/M08), 1 BLOCKED (`live.source`,
GATE-LIVE). `/healthz` returning 200 never upgrades any of them.

## 5. Demo mode

Enabled only by `VITE_OPERATOR_DEMO=true` (development preview). It renders fixed
fixtures from `api/demo.ts` behind a persistent `DEMO / DỮ LIỆU MÔ PHỎNG` banner,
labels every local mutation `Mô phỏng cục bộ — không gửi tới máy chủ`, and never
claims a real stream, a real player or an authenticated operator. Production mode
(the default, and the only mode CI builds) shows `UNAVAILABLE` states and an
empty session list instead of fabricated rows.

## 8. Development integration

`vite.config.ts` proxies `/healthz`, `/readyz` and the future `/admin/v1` to
`TTG_OPERATOR_BACKEND_URL` (default `http://127.0.0.1:8080`). PostgreSQL is never
exposed to the browser, no public IP is hardcoded and no TLS material is assumed.

Scripts: `tooling/operator-run.ps1|sh` (checks Node 24, runs `npm ci` when needed,
starts Vite, `--demo` opt-in), `tooling/operator-test.ps1|sh` (npm ci → typecheck
→ lint → tests → build, failing fast with the step's exit code).

## 10. CI

New `frontend` job: pinned `actions/checkout` and `actions/setup-node@v6` SHAs,
Node 24.21.0, `npm ci`, lockfile consistency check (exact pins, matching lock),
typecheck, lint, tests, production build, and a bundle scan for credentials/DSNs.
The existing `backend`, `unity` (static validator) and `tooling` jobs are
unchanged; `tooling` additionally runs the Unity result-evaluation regression.

A browser E2E runner is **not** available in this repository, so no Playwright
smoke test is claimed. The equivalent flows (startup, demo labelling, backend
unavailable) are covered by component tests in jsdom; a real-browser runner
remains open work for M08.

## 11. Limits

- No real authentication: M05 owns login, session cookies, CSRF and RBAC
  enforcement. Client-side permissions are UI affordances only.
- No admin endpoints exist, so villages/sessions/moderation render UNAVAILABLE in
  production; demo mode is the only place they are interactive.
- `nginx`/TLS deployment, CSP headers and serving the SPA from the Go binary are
  deployment work (M08/M10), not part of this foundation.
- Accessibility was exercised with Testing Library queries and keyboard
  interactions; no automated axe audit or screen-reader pass was run.

## 12. Verdict

**PASS** for M01-W0105: real dependencies, real tests, a real production build,
and an honest boundary around the features the backend does not have. M01 stays
**IN_PROGRESS** (W0106 still open); M07 is **NOT_STARTED** and its pages are
shells only.
