# M04-W0402 — Atomic reducer tick, applied events and transactional outbox

Status: **PASS** for W0402's fenced reducer transaction. M04 remains IN_PROGRESS;
W0403–W0407 are NOT_STARTED. This is not full checkpoint/replay, crash restart, PITR or
M08 load evidence, and it does not claim full QA-DB-05/06/07.

## 1. Architecture

New package `backend/internal/reducer`:

- `Reducer.Step(ctx, lease, sessionID)` calls W0401
  `writer.Manager.WithFence` and performs exactly one logical transition.
- `runtime.go` defines the private durable runtime envelope: complete M02
  `domain.SessionState`, the `simulation.CheckpointEnvelope` (pending role/ballot queues,
  canonical state hash, private digest), next-wave input metadata and a SHA-256 runtime
  digest. JSONB normalization cannot break the digest because it covers the checkpoint
  envelope rather than raw state bytes.
- `reducer.go` loads session/village/input rows, accepts commands with their original
  committed `accepted_tick`, advances/rolls over with the pure simulation APIs, and
  computes the canonical hash.
- `persist.go` writes every authoritative effect in the same fenced transaction.

No M02 rules, canonical v2 hash, `ttg-rules-v1`, combat math or M03 ingestion semantics
were changed.

## 2. Transaction order and locking

Inside the W0401 fence (lease row lock, then session row lock):

1. Load committed session/village/runtime.
2. Select unapplied inputs for the current committed `accepted_tick` in `input_seq`
   order; verify older unapplied inputs are represented by runtime queues/next-wave
   metadata.
3. Decode role/vote payloads and accept using the original accepted tick.
4. Advance exactly one tick (or start/rollover) with `simulation.AdvanceWithRoles`.
5. Persist session state/tick/lifecycle/hash/runtime, materialized village/member/XP/
   ballot rows, per-input `applied_at_tick`, domain events and stream outbox.
6. Commit only through `WithFence`; callback errors roll back.

Lock order is `writer_leases` → `sessions` → input/village/member/outbox rows. W0305
ingestion locks the session only and does not require the lease; a concurrent append
blocks on the session row and resumes after the reducer commit, as tested.

## 3. Revision and runtime

Migration `00006_reducer_revision.sql` adds `sessions.reducer_revision BIGINT NOT NULL
DEFAULT 0 CHECK >= 0`. It is strictly monotonic per session and is independent of
`input_sequence`, `writer_epoch`, `wave_tick` and `stream_sequence`. Domain events and
outbox rows use this revision. `runtime_state` carries the complete continuation state,
not only the public canonical projection; malformed/incomplete/digest-mismatched runtime
data fails closed. A legacy session without runtime can only initialize from a pristine
waiting state; otherwise it fails closed.

## 4. Input ordering and QA-DB-06

Real PostgreSQL test `TestFutureWaveInput50WaitsWhileInput51Applies`:

- Input 50 (lower `input_seq`) is accepted at the tick-2800 RESULTS boundary and targets
  wave 2 at tick 0.
- Input 51 is accepted at 2799 and targets wave 1 at tick 2800.
- The first transition applies **51 exactly once**, leaves **50 unapplied**, and records
  50 in durable next-wave metadata.
- Input 50 remains pending through RESULTS and is applied **exactly once at rollover
  (tick 3000)**, promoting its actor into wave 2.
- No global applied-sequence watermark is used; input 50 is never skipped because 51
  has a higher sequence.
- Neither event creates duplicate membership, XP, ballot or outbox records.

Applied status is per event: current-wave due commands are marked at the new committed
tick; next-wave commands remain NULL until rollover; no-op/cooldown commands are still
marked once with their truthful final outcome.

## 5. Gameplay persistence

Tests cover:

- first join: one durable role starts wave 1 at tick 0, member row, session epoch/tick,
  domain events and outbox in one commit;
- quiet tick: tick advances with no applied input and no fabricated events;
- role change: first switch allowed, second switch inside 600 ticks rejected while the
  input is still terminally applied once;
- even-wave voting: ballot A applied at 800, latest B replaces it at 801 with one row;
- settlement at 2800: state result is non-pending, `wave_result` domain/outbox rows exist;
- boss wave 5: `boss_spawned` at 2600 in both domain events and outbox;
- 1,000 duplicate role commands: one member and no XP inflation, all 1,000 inputs
  terminally applied;
- village resources/XP seeded into runtime are materialized exactly into `villages` and
  `session_player_progress` in the same commit;
- runtime hash reload matches `sessions.last_state_hash`.

## 6. Failure injection and commit unknown

`TestFailureInjectionRollsBackEveryStage` injects a failure at 13 points: after load,
before/after selection, after apply, after session/village/members/XP/ballots/domain
events/outbox/applied inputs and before commit. Every case leaves `wave_tick=-1`,
`reducer_revision=0`, no members/domain/outbox rows and `applied_at_tick NULL`.

`TestAmbiguousCommitReconcilesDurableResult` uses a controlled fencer that commits then
returns `ErrCommitUnknown`; the reducer verifies session revision/hash and returns
`Reconciled=true` only after the durable record proves the commit. A controlled
uncommitted unknown outcome fails closed with no tick change.

`TestStaleWriterCannotAdvanceReducer` takes over the lease at a higher epoch and proves
the old writer cannot change tick or emit outbox rows.

## 8. Privacy and security

- Outbox/domain payloads are the public `simulation.Event` JSON; tests assert no actor
  key leakage. Runtime state is private and never placed in the outbox.
- No actor key, HMAC secret, viewer ID, provider event ID, raw comment or alias is
  written to public events.
- SQL is parameterized; errors are typed and do not echo IDs or SQL.
- No unfenced authoritative write; `WithFence` owns commit/rollback; no WebSocket publish
  occurs inside the transaction.
- No HTTP endpoint, TikTok integration or gameplay rule change was added.

## 9. Known limitations

- W0403 canonical checkpoints/replay and W0404 SQL crash restart/PITR are not implemented;
  this is not full checkpoint replay evidence.
- No outbox publisher/WebSocket (M05); outbox rows remain available for later delivery.
- QA-DB-05/06/07 are partial: full reducer/outbox atomicity under M08 sustained load,
  crash recovery and mixed pause/outage acceptance remain later work.
- The reducer loads at most 5,000 eligible inputs per transition and fails closed with
  `ErrInputBacklog` beyond that; no M08 throughput claim.
- Runtime state is a private JSON envelope, not a W0403 canonical checkpoint; it is
  integrity-checked but not externally signed.
