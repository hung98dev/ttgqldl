# M03-W0303 — Source provenance hardening and scoped HMAC identity

replay snapshots, versioned scoped HMAC ActorKeys, retained-key candidate derivation,
session-scoped ephemeral identities and structural alias sanitization. It does **not**

## 2. Mock immutability policy

`NewMock`/`NewMockWithEvents` validate then store a deep copy of the complete script.
Strings are immutable in Go; the only mutable payload is `*time.Time`, which is cloned
at construction and cloned again for every delivery. The adapter never exposes internal
storage. Tests cover caller slice/field/timestamp mutation, sink mutation of a delivered
timestamp, delivery after mutation, reconnect after mutation, and source-identity
stability.

## 3. Source-script identity format v2

`mockSourceID` now hashes a domain-separated, versioned, length-prefixed encoding:

```text
lp("ttg-source-script") || u64be(2) || lp(session_id) || u64be(event_count)
for each event in script order:
    lp(provider) || lp(source_session) || lp(provider_event_id) ||
    lp(provider_viewer_id) || lp(alias) || lp(message) || u64be(kind) ||
    lp(received_at RFC3339Nano UTC) || u64be(upstream_present) ||
    [lp(upstream_at RFC3339Nano UTC)]
```

Every variable field is length-prefixed; fixed order; event count and order are bound;
timestamp presence and instant are bound. Tests prove every field, timestamp nil-vs-
present, order and session change the identity, and delimiter-shaped identifiers no
longer collide (`e|v`/`x` vs `e`/`v|x`). The cursor format is unchanged; the digest is
the source identity, so version-1 cursors fail closed with `ErrCursorMismatch` (test
reconstructs the old v1 digest to prove it).

## 4. Replay provenance

`NewReplay` verifies the manifest digest and record count, resolves symlinks and rejects
paths whose real target leaves the configured fixture directory. `Start`/`Reconnect`
then copy the fixture through SHA-256 + a record counter into a private `0600` temporary
snapshot, verify digest and record count again, rewind, and stream **only that snapshot**.

- Mutation before Start: `ErrFixtureDigest`, zero events delivered.
- Mutation during delivery: remaining events still come from the verified snapshot.
- Replacement before reconnect: reconnect re-verifies and fails closed with
  `ErrFixtureDigest`.
- Digest/record-count/manifest-schema/path-traversal/symlink-escape attempts fail
  closed. Symlink escape is skipped on this Windows host (symlink privilege) and runs
  on Linux CI.
- Bounds preserved: 64 KiB record limit, 1 MiB manifest, 32 KiB copy buffer, 4 KiB
  scanner start; the snapshot is a file, never an unbounded RAM slice. 50,000-record
  fixture: 94 ms stream + resume at 49,999.

## 5. ActorKey construction

```text
ActorKey = lowercase_hex(HMAC-SHA256(secret,
    lp("ttg-actor-key") || u64be(1) || lp(key_version) ||
    lp(provider) || lp(provider_version) || lp(broadcaster_key) || lp(viewer_id)))
lp(s) = u64be(len(s)) || s
```

The tuple binds provider, provider identity version, broadcaster/village scope, stable
provider viewer id and key version. Display alias, comment text, event timestamp,
sequence, gift data, IP, fingerprint and per-message randomness are absent. Output is
validated with the existing `domain.ActorKey.Valid()` (no duplicated validator) and is
always 64 lowercase hex characters. No NFC/trim/case folding: distinct raw identifiers
remain distinct; mixed-script viewer ids are opaque and do not collide.

## 6. Key management and versioning

- Secrets are explicit `[]byte` injections: 32..4096 bytes, degenerate (all-identical)
  material rejected; no default, generated or embedded production secret.
- Key versions match the DB CHECK shape `[A-Za-z0-9._:-]{1,32}`.
- `KeySet`: one active version + zero or more retained versions; duplicate labels
  (including active repeated in retained) rejected; unknown version rejected.
- Candidate order is deterministic: active first, retained sorted by label, independent
  of construction order.
- Secret bytes are private; `String`/`GoString` on Key, KeySet, Result and Ephemeral are
  redacted; errors contain field categories only, never raw ids or secrets.
- Thread-safe immutable sets, no global registry, no DB/HTTP/TikTok dependency.

## 7. Rotation boundary

`Candidates(input)` re-derives the same raw viewer id under active + retained versions.
An old HMAC digest cannot recover the raw viewer id when the secret changes; candidates
therefore require the original identifier transiently. Durable alias resolution, appending
the new-version alias, retiring old aliases/keys and the migration gate are **M04
persistence work and are not implemented**; rotation is not claimed complete.

## 8. Ephemeral identity

`EphemeralConfig{SessionID, Secret, ExpiresAt, Now}` with explicit injected synthetic
secret and clock. HMAC domain `ttg-ephemeral-actor-key` binds session id + viewer id;
same viewer/session is stable, different sessions are not correlatable, expiry
(`!now.Before(expiresAt)`) fails closed, missing/short/degenerate secret, zero expiry,
nil clock and invalid viewer/session are rejected. Results carry `Ephemeral=true` and
`KeyVersion="ephemeral-v1"`; they must never be persisted as provider aliases and never
imply provider-backed continuity.

LIVE policy: the provider-backed API requires a non-empty stable viewer id and returns
`ErrMissingViewerID` otherwise; there is **no ephemeral fallback** and no LIVE adapter or
authorization claim. P1 remains BLOCKED.

## 9. Privacy and alias boundary

`SanitizeDisplayAlias` enforces UTF-8, 256-byte database backstop, 64 graphemes, no
controls/format characters, no leading/excessive combining marks, rejects URL-like and
markup content, honors hidden/erased/opted-out states (no display), and uses a safe
fallback (`Villager`, or a caller fallback only if itself structurally safe). Alias never
enters derivation. This is structural only: profanity/moderation/audit remain M05/M08
gates, so QA-SEC-06 is not claimed. Source acceptance of an alias does not authorize
publication.

## 10. Independent golden vectors
