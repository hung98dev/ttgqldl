# M04-W0403 — Canonical checkpoints and deterministic replay

Status: **PASS** for W0403's durable checkpoint/replay boundary. M04 remains IN_PROGRESS;
W0404–W0407 are NOT_STARTED. This is not SQL crash restart, PITR, privacy-erasure or
retention completion.

## 1. Durable checkpoint format

`ttg.checkpoints` already existed. W0403 stores a versioned private wrapper in
`state_json` (checkpoint format **1**):

- `format=1`;
- session/village identity;
- `ttg-rules-v1`, canonical schema v2;
- replay cursor: reducer revision, wave number/tick, input sequence, stream sequence,
  checkpoint reason;
- W0402 runtime envelope (complete `domain.SessionState`, M02 checkpoint envelope with
  role/ballot queues and private digest, next-wave input metadata, runtime digest);
- SHA-256 checkpoint binding over identity + cursor + runtime digest.

The canonical `state_hash` column remains the RFC8785 schema-v2 hash. The replay cursor
is covered by the checkpoint digest; changing it without recomputing the digest fails.
The cursor is not authenticated against an attacker who can rewrite both content and
unkeyed hashes; this is corruption detection, not a trusted external anchor.

Migration `00007_reducer_transitions.sql` adds an immutable one-row-per-revision journal
(`operation`, wave/tick, state hash). It is the minimum history needed because
`input_seq` and `applied_at_tick` do not encode the ordered quiet/pause/start/rollover
transitions. Journal rows and checkpoints are written inside the W0402 fence transaction.

## 2. Checkpoint scheduling and atomicity

Created at tick 0 (start/new wave), every 600 running ticks (600/1200/1800/2400),
tick 2800 settlement and tick 3000 control boundary. A checkpoint write is part of the
same W0402 transaction as state/tick/hash/revision/materialized rows/domain events/
outbox/applied inputs; failure rolls all of them back. `(session_id,revision)` insertion
is idempotent; a conflicting hash at the same revision fails closed.

The checkpoint schedule was tested at real PostgreSQL ticks 600, 1200, 1800, 2400,
2800 and 3000/new-wave tick0, plus the initial tick0 checkpoint. A failure injected
after checkpoint insertion leaves no checkpoint, tick, member, XP, domain-event, outbox
or applied-input row.

## 3. Replay engine

`Reducer.VerifyReplay(session, targetRevision)` and
`VerifyReplayFrom(session, checkpointRevision, targetRevision)`:

1. Load the selected/latest checkpoint at or before target.
2. Verify format, identity, rules, canonical schema, cursor and digest.
3. Decode and verify the complete W0402 runtime/private queues.
4. Load the immutable `input_events` history (including applied rows) ordered by
   `input_seq`; reject duplicate sequences.
5. Load contiguous `reducer_transitions` rows after the checkpoint; reject gaps.
6. Rebuild state by calling the same M02 `computeTransition`/`AdvanceWithRoles` path
   used by production, selecting inputs by original `accepted_tick` and preserving
   next-wave metadata.
7. Compare each journal operation/wave/tick/state hash.
8. Compare the final canonical hash and, at the current revision, the complete private
   state/queues/queued-next metadata with `sessions.runtime_state`.

Replay is read-only: no authoritative row, XP, outbox, checkpoint or journal is written.
A missing checkpoint, missing journal revision, missing/mutated input, checkpoint
corruption, cursor tampering or private-state mismatch returns a typed error.

## 4. Determinism campaign

`TestHundredDistinctReplayPositions` runs **100 distinct target revisions** (revisions
1..100) against real PostgreSQL checkpoint/journal/input rows. All 100 verify with zero
state/hash/private-state mismatches; the session revision and outbox remain unchanged.
`TestReplayAcrossBossAndSettlement` replays 400 transitions from checkpoint tick2400
through boss spawn at2600 and settlement at2800, including final private state.

Checkpoint at tick600: `state_json` text **2,104 bytes**, Step (including checkpoint
insert) **~18 ms**, replay verification of the checkpoint itself **~5 ms** on the local
PostgreSQL 18.6 Docker environment. The 100-position campaign completes in ~1.4 s
(quiet ticks); these are not M08 load measurements.

## 5. Future-wave input 50/51

The W0402 real-PostgreSQL scenario is replayed across a checkpoint:

- input 50 (lower sequence, target next wave) is in the tick-2800 checkpoint runtime
  metadata;
- input 51 is applied at 2800 exactly once;
- input 50 remains unapplied through RESULTS;
- rollover applies 50 exactly once at 3000 and promotes its actor;
- replay from the checkpoint reproduces the same canonical hash and private state;
- no global applied-input watermark skips 50.

## 6. Corruption and adversarial tests

Real checkpoint/journal mutations all fail closed: modified state hash, modified cursor,
unsupported format, wrong rules, malformed JSON, missing journal revision, wrong journal
hash, missing checkpoint, deleted input event, mutated input payload. Missing history
without a checkpoint returns `ErrReplayNoCheckpoint`; no replay PASS is fabricated.
XP/reward/materialized tables are never mutated by verification.

## 8. Privacy and security

Checkpoints are private DB rows; no HTTP export endpoint was added. They contain
pseudonymous actor keys but no raw viewer IDs, provider event IDs, comments, aliases,
HMAC secrets or private provider data. Replay diagnostics are typed and do not echo
payloads. No gameplay rule, canonical v2 hash, M03 ingestion or writer fence was changed.

## 9. Known limitations

- W0404 SQL crash restart, PITR/backup restore and recovery-after-crash are not implemented.
- W0406 privacy-erasure cutoffs, anonymized checkpoints and deletion-ledger restore are not
  implemented; checkpoints can support them but this is not claimed.
- W0407 retention pruning is not implemented; W0403 documents the checkpoint-coverage
  requirement but does not authorize destructive purges.
- No M05 outbox publisher/WebSocket; outbox remains durable for later delivery.
- 100-position campaign is deterministic quiet-tick heavy; boss/settlement replay covers
  one 400-transition run, not M08 sustained load.
- Checkpoint/replay latency is local Docker measurement, not production SLO.
