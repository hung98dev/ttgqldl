# POSTGRESQL 18.6 DATA, TRANSACTIONS AND RECOVERY

## Ownership, isolation and transactional boundaries
Only PostgreSQL is authoritative. One Go simulation leader per village holds an exclusive database-backed lease with fencing epoch and heartbeat. An expired lease does not grant a previous owner authority: each write compares the fencing epoch; stale owner writes fail. Source ingestion and simulation reducer are separate transactions but **never** acknowledge an authoritative mutation before its durable commit. Use serializable or appropriately row-locked transactions for sequence/ownership; handle SQLSTATE 40001/40P01 retries with jitter, max three retries then explicit 503/degraded. No connection pool unlimited growth. No schema migration on hot production startup. PostgreSQL 18.6 exact docker digest pinned in M01.

## Schema contract — M01 bootstrap migrations
Required tables and constraints (actual executable, forward-tested SQL is M01 deliverable, not prose):
- villages: id UUID PK, broadcaster_key CHAR(64) UNIQUE (scoped pseudonym), level SMALLINT CHECK 1..50 DEFAULT1, wall_tier SMALLINT CHECK1..20 DEFAULT1, wall_hp BIGINT CHECK>=0 DEFAULT1000, townhall_hp BIGINT CHECK0..500 DEFAULT500, wood/stone/food BIGINT CHECK0..1000000 DEFAULT 400/250/300, construction_work BIGINT CHECK>=0 DEFAULT0, total_wins BIGINT CHECK>=0 DEFAULT0, consecutive_wins SMALLINT CHECK0..10 DEFAULT0, consecutive_losses SMALLINT CHECK0..3 DEFAULT0, created_at/updated_at TIMESTAMPTZ; enforce wall_hp<=1000+200*(wall_tier-1).
- sessions: id UUID PK, village_id FK, mode TEXT CHECK mock|replay|authorized_live, lifecycle TEXT CHECK waiting|running|paused|source_disconnected|storage_unavailable|stopped, wave_no BIGINT >=1, wave_tick INT -1..3000, privacy_epoch BIGINT CHECK>=0 DEFAULT0, rules_version TEXT NOT NULL, writer_epoch BIGINT DEFAULT0, input_sequence BIGINT DEFAULT0, stream_sequence BIGINT DEFAULT0, last_reduced_tick INT DEFAULT -1, last_state_hash CHAR(64), runtime_state JSONB, pause_reasons JSONB DEFAULT '[]'::jsonb, started_at, stopped_at, last_heartbeat_at. Unique partial index for one active session per village when lifecycle!=stopped.
- players: id UUID PK, village_id FK, actor_key CHAR(64) NOT NULL, ephemeral BOOL NOT NULL, alias TEXT length <=128 bytes, hide_alias BOOL DEFAULT FALSE, lifetime_xp BIGINT>=0, created_at, last_seen_at, UNIQUE(village_id,actor_key). Ephemeral actors are deleted when session expires; do not link session anonymous user to another live.
- session_player_progress: session_id FK, actor_key CHAR(64), session_xp SMALLINT CHECK0..300 DEFAULT0, PRIMARY KEY(session_id,actor_key).
- wave_members: session_id FK, wave_no BIGINT>=1, actor_key CHAR(64), role TEXT CHECK builder|guard|fighter, joined_tick INT, last_change_tick INT NULL, first_switch_used BOOL NOT NULL DEFAULT FALSE, last_update_seq BIGINT, xp_awarded BOOL DEFAULT FALSE, PRIMARY KEY(session_id,wave_no,actor_key). Pending-next-wave joins use wave_no=current+1.
- ballots: session_id FK, wave_no BIGINT, actor_key CHAR(64), option CHAR(1) CHECK A|B|C, input_seq BIGINT, PRIMARY KEY(session_id,wave_no,actor_key).
- input_receipts: session_id FK, provider_source TEXT, provider_event_id TEXT, inserted_at TIMESTAMPTZ, UNIQUE(session_id,provider_source,provider_event_id); NEVER insert NULL-ID as empty; optionally separate best-effort TTL cache. Index TTL cleanup. Only accepted game-affecting events must be durably deduped; repeated same-role chat can be rejected by bounded cache and metric before DB.
- input_events: session_id FK, input_seq BIGINT, accepted_tick INT, scheduled_tick INT, applied_at_tick INT NULL, wave_no BIGINT, actor_key CHAR(64), kind TEXT, canonical_payload JSONB, rules_version TEXT, inserted_at TIMESTAMPTZ, PRIMARY KEY(session_id,input_seq). Partial index (session_id,wave_no,scheduled_tick,input_seq) WHERE applied_at_tick IS NULL. Pending next-wave events MAY have a lower input_seq than later current-wave events; a single global applied-sequence watermark must not skip them.
- checkpoints: session_id FK, wave_no BIGINT, wave_tick INT, input_seq BIGINT, revision BIGINT, state_json JSONB, state_hash CHAR(64), rules_version TEXT, created_at TIMESTAMPTZ, PRIMARY KEY(session_id,revision). Index newest per session.
- domain_events: session_id FK, revision BIGINT, event_index INT, event_type TEXT, payload JSONB, created_at TIMESTAMPTZ, PRIMARY KEY(session_id,revision,event_index). Must not store unmoderated raw text.
- stream_outbox: session_id FK, stream_seq BIGINT, revision BIGINT, type TEXT, payload JSONB, created_at TIMESTAMPTZ, PRIMARY KEY(session_id,stream_seq), checkpoint_ref optional.
- operator_accounts: id UUID PK, username CITEXT or text unique lower index, password_hash TEXT with Argon2id, role admin|operator|viewer, disabled_at, created_at.
- operator_sessions: id UUID PK, account_id FK, secret_hash CHAR(64), expires_at, revoked_at; secrets hashed not stored plain.
- operator_audit: id BIGINT identity PK, actor_id UUID, action, target, reason, created_at, ip_hash optional; minimum privilege for audit reads.
- writer_leases: village_id PK FK, writer_epoch BIGINT, owner_instance TEXT, leased_until TIMESTAMPTZ.
Additional tables MUST exist: admin_idempotency_keys(account_id,route,key,request_hash,response_status,response_json,created_at,expires_at,PRIMARY KEY(account_id,route,key)); privacy_tombstones(id UUID PK,actor_ref_protected TEXT,scope TEXT,created_at TIMESTAMPTZ,restore_applied_at TIMESTAMPTZ); broadcaster_source_bindings(village_id FK,provider,broadcaster_key,approval_ref,permission_expires_at). All FK cascade policy explicit: session game logs cascade only by audited retention purge; player deletion does not accidentally cascade authoritative wave outcomes. Every bigint checked for safe SQL/JSON protocol ranges. No schema in public PostgreSQL search_path for API role; grants strictly least-privilege.

## Transaction protocols
Ingest: validate adapter provenance, scope, ID and grammar; in transaction lock session row, allocate input_seq, determine target_wave and scheduled_tick = committed_tick+1, insert receipt for stable event ID, append immutable validated input_event; do NOT mutate authoritative wave_members or ballots in ingest. Reducer applies accepted commands and cooldown exactly once. Duplicate provider ID returns prior receipt with no second event. During RESULTS target next wave tick0, during WAITING initial valid role starts wave at tick0. Acknowledge only after committed append.
Reducer: read session row FOR UPDATE and verify writer epoch; pull unprocessed input_events ordered by input_seq with wave_no=current and scheduled_tick<=boundary tick, mark each event as applied in the SAME reducer transaction (including cooldown/no-op outcomes); apply only once; advance logical tick and player roles, settle economic state, checkpoints and game event/outbox. Write updated village+session and outbox in same DB transaction. If commit fails, publish NOTHING. Snapshots every 600 ticks and wave end; tick/role commands since last full snapshot are recoverable by reading ordered immutable input_events. If simulation cannot persist a tick, freeze until DB back.
Recovery: acquire new epoch, load latest valid checkpoint, verify hash, replay accepted inputs up to last persisted boundary, never advance beyond committed tick using wall clock. Outbox might contain committed messages not published: replay over WebSocket from stream_seq if retained; otherwise send full projected snapshot and new cursor. Checkpoint hash mismatch => fail closed/incident, no auto-repair. Crash tests kill process before/after commit and verify no duplicate XP, resources, votes or rewards.
Database partition/retention: input_receipts 24h minimum after session or provider replay horizon (choose longer verified), input_events until a verified checkpoint covers them and 30-day diagnostics expiry, stream_outbox 7 days or snapshot-resync always available, operator audit 180 days (actual privacy/legal policy may require different retention; privacy owner gate). Raw comment body never stored outside bounded redacted debug traces.

## Privacy erasure versus replay (non-negotiable)
Individual erasure on active wave: suppress alias immediately; revoke future contribution at next boundary and queue deletion. At next committed wave boundary, create an anonymized aggregate checkpoint, revoke personal mapping, delete personally linkable player, membership, pending votes and pre-checkpoint per-player input history once safe, update privacy_epoch; only replay since new checkpoint is promised. Past settled aggregates and irreversible resource totals remain as nonidentifying numeric totals, not actor mappings. Refresh the canonical hash at privacy boundary and record verifiable privacy_epoch audit without username. No user identity may be resurrected by restoring old backups: restore pipeline reapplies deletion tombstone ledger kept separately with retained anonymous cryptographic markers. Delete tests include live, snapshot, backup restore and cross-session consistency.

## Two distinct snapshot types
- PRIVATE canonical reducer state: complete sorted wave members, roles, votes, HP subpools, resources, counters, tick, pending roles, input sequence, privacy_epoch, rules_version; may be >1MiB and never sent to broadcaster video.
- PUBLIC projected view: aggregate counts, wave stage, lane statuses, wall/townhall, resource rounded progress, selected top 12 moderated alias samples, vote counts, contribution highlights, source health; target <=32KiB and HARD max 128KiB. Stream never exposes ActorKey/HMAC/real provider IDs.
Canonical JSON hash via RFC8785 for state, actor list sorted by actor_key bytes, enemy lanes 0..2 archetypes0..3. Domain serialization version must be part of hash. Input_events/telemetry/wall timestamps are omitted.

## Executable storage and concurrency clarifications
- Initialize sessions with wave_no=1,wave_tick=-1,lifecycle=waiting. The first valid role event is stored as target wave1 scheduled_tick0 and causes atomic StartWave(-1->0). On RESULTS input targets wave_no+1 tick0; tick3000 promotes pending membership and starts next wave without re-commenting or enters WAITING=-1.
- Input_seq is monotonic per session but NOT a global processing cursor. Current wave event input_seq=51 can be applied before earlier input_seq=50 queued for NEXT wave. Store per-event applied_at_tick with explicit wave_no and replay history retained; recovery replays immutable accepted inputs, even if previously marked applied. Never permanently skip future-wave events.
- For load, append validated commands in per-village batches up to 256 or flush every 50ms; allocate consecutive input_seq under session row lock and acknowledge only after commit. Use bounded queues and truthful valid-drop accounting. Avoid one synchronous session-row transaction for each raw comment.
- Writer lease acquisition/renewal uses atomic DB-clock checks, increments writer_epoch on takeover and every authoritative reducer state write compares epoch. A stale writer cannot persist tick, events or rewards. Pauses form independent sorted reasons operator/source/storage; gameplay advances only when all reasons cleared.
- Tick commit atomically stores session tick/lifecycle, relevant runtime_state (enemy HP, vote, paused reasons), materialized village counters, marked applied input events, memberships, ballots, stream_outbox and domain_events. Write periodic FULL canonical checkpoints at tick0, every600 ticks, tick2800/3000 and after privacy erasure. Between checkpoints, reconstruct pure state from immutable event log and deterministic tick progression; compare with materialized state and last_state_hash at boundaries.
- Canonical RFC8785 hash covers exactly schema_version, rules_version, session_id, village_id, wave_no, wave_tick, lifecycle, defeated, wall_tier, wall_hp, townhall_hp, wood, stone, food, construction_work, total_wins, consecutive_wins, consecutive_losses, anchor_population, difficulty, base_hp, lane_pools, boss_hp, vote, members, queued_next_wave, privacy_epoch. Members sorted by actor_key with actor_key,role,joined_tick,last_change_tick,first_switch_used,xp_awarded; lane_pools exactly west/center/east each runner_hp,grunt_hp,brute_hp; vote counts A/B/C and chosen. All nullable fields explicit null, positive integers representable in JSON safe range, larger sequence values decimal strings. NO wall times/aliases/network/cosmetic RNG.
- Privacy erasure makes a new anonymized checkpoint + privacy_epoch boundary and prunes identifying inputs covered by checkpoint; protected tombstone ledger survives backup/restore and must be reapplied before accepting traffic. Deletion cannot retroactively re-run a historical battle with a vanished identity. Test identity resurrection, future-wave queued IDs and restore.

## Privacy restore ledger and HMAC rotation — critical explicit dependency
- The `privacy_tombstones` SQL table is NOT enough for safe erasure after restoring an older PostgreSQL backup, because the backup predates later deletions. Export each deletion event atomically (transactional outbox) to an **independent encrypted append-only ledger on separately backed-up storage** with fsync/durable acknowledgment. Restore procedure MUST obtain the ledger through the restore cutoff time, replay tombstones, purge old actor mappings and re-snapshot BEFORE exposing API/WS; if the external ledger is unavailable or lagging, RESTORE FAILS CLOSED. No claim of permanent erasure before external ledger acknowledgment. Ledger backup recovery keys must be separately tested.
- Add `actor_identity_aliases` table `(village_id,actor_key CHAR(64),key_version TEXT,player_id UUID FK,created_at,PRIMARY KEY(village_id,actor_key,key_version))`. Rotate HMAC without raw IDs at rest: while a player authenticates with lawful provider ID, compute candidates from active+retained old in-memory versioned keys, match alias, map to stable player ID, append new-version alias, then retire old keys only after retention/migration gate. Do not presume an old HMAC can be converted to a new HMAC without original ID or key. Stored identities remain pseudonymous sensitive data.
