# GAME RULES — BINDING

## Session/village and progression
One broadcaster owns one village (broadcaster key stable, privacy-protected). Session has one active wave at a time. A village keeps level 1..50, wall tier 1..20, XP cosmetics, resources and persistent total_wins; starts level=1, wall tier=1, wall_hp=1000, townhall_hp=500, wood=400, stone=250, food=300, construction_work=0; resources capped at 1,000,000 each. Initial wave_number=1, consecutive_wins=0. All backend arithmetic signed int64 checked for overflow, never floats.
One wave is 300s at 10Hz (ticks 0..2999). Start only on first eligible role message after operator START; status WAITING before that. PHASE PREP [0,160s); ASSAULT [160,260s); FINALE [260,280s); RESULTS [280,300s). Boss on wave_number divisible by 5. Engine only advances simulation time while RUNNING; PAUSED, PROVIDER_DISCONNECTED, STORAGE_UNAVAILABLE freeze time. At RESULTS completion, if NEXT-wave roles are queued, promote them atomically and start the next wave at tick0; otherwise WAITING until new eligible join. Queued viewers MUST NOT be required to comment again.

## Exact player action model
Text exact role commands XAY/THU/DANH and BUILD/DEFEND/ATTACK; lower-case, trim, Unicode NFKC, fold Vietnamese diacritics incl. đ->d, collapse ASCII/Unicode spaces; only one canonical token accepted; punctuation and substrings are invalid. One role selection registers player for CURRENT wave, except RESULTS where it queues NEXT wave; ONE role contribution at each 20s resolution boundary until RESULTS, even if user sends no more messages. Thus viewers never need to repeatedly comment. Last VALID role accepted before a boundary takes effect on the next boundary; the first role change after joining is permitted immediately, while subsequent changes require >=600 simulation ticks since the last accepted role change; additional changes are ignored/acknowledged as cooldown, NEVER modify previous role. Repeated identical messages are no-op. A player joining RESULTS is assigned to NEXT wave and receives immediate visible 'NEXT WAVE' receipt, without counting as present now; when next wave starts, registration transfers atomically and persists for that wave. A participant joining a paused wave receives queued role only if source is connected, applied on resume without advancing simulation clock. Player roles expire at wave rollover; previous wave XP/identity persist.
A player earns +10 XP once per wave with at least one eligible contributing interval; no XP per chat, repeated comment, vote or gift. XP cap per player per SESSION = 300 and level is cosmetics only. A newly joining viewer contributes equally in the same role as veterans. Display actual accepted count and source health, not fake viewers. IDs are scoped HMAC identities from authorized stable provider ID, otherwise session-only ephemeral with honest limitations.

## Roles and economy
At every tick multiple of 200 (20-second boundary), except results phase and tick 0, count active registered participants B=builders, G=guards, F=fighters. Population anchor P = max(1, unique registrations in the wave at tick 1600), capped at 10,000 for difficulty coefficients, while all valid viewers beyond 10k still counted in contributions with sqrt saturation cap=10,000 per role. New viewers after tick1600 increase effort but cannot increase that wave's enemy HP, encouraging newcomers.
Builder generation each interval: wood += 2*isqrt(B)+floor(B/50); stone += isqrt(B)+floor(B/500), cap overflow at 1,000,000. Repair capacity = 8*isqrt(B). First generate wood+stone, then repair min(repair_capacity, wall_max-wall_hp, 5*wood); wood cost ceil(actual_repair/5), rounded integer. When wall has no missing HP, leftover capacity becomes construction work. Otherwise leftover capacity also becomes construction work after repair. Construction work accumulates only if B>0, cap progress at threshold until upgrade. Upgrade automatically if construction_work >= 200*wall_tier AND stone >= 100*wall_tier AND tier<20: subtract both costs, increase tier by 1, new wall_max=1000+200*(tier-1), add 200 to wall_hp (cap to new max); at most ONE tier upgrade per boundary; leave excess construction_work for next boundary. When at tier20 work is ignored.
Guard block = 8*isqrt(G) each COMBAT boundary, cannot be banked. Fighter attack = 14*isqrt(F), cannot be banked. If 1<=P<=10, non-viewer militia attack bonus max(0,40-4*(P-1)) per COMBAT boundary; if P>10 militia attack=0. Show any militia as system assistance, never count it as a viewer. No NPC appears in statistics as a user or earns XP. All isqrt integer floor.

## Enemies / waves / boss
At tick 1600 snapshot P, difficulty d=min(10,1+consecutive_wins); initial ordinary HP base_hp = max(1, floor((40+8*d+38*isqrt(P))*(100-15*min(consecutive_losses,3))/100)), difficulty reduction is transparent 'recovery modifier' shown on HUD. Enemy pools: west=floor(base_hp*34/100), center=floor(base_hp*32/100), east=base_hp-west-center. Each lane subpools runner=25%, grunt=55%, brute=remainder (integer floors); each subpool has only HP counter and visual archetype, not 10,000 enemy entities. Normal units spawn at tick 1600; deterministic visual counts are for presentation, not hit points.
Boss wave: at tick 2600, spawn boss pool with HP ceil(base_hp/5); non-boss wave: no new enemy, but FINALE warning/visual climax. Boss is in center lane and is attacked after all ordinary subpools in that lane. One initial fixed enemyHP pool for each wave; no hidden rubber-banding after tick1600.
At COMBAT boundaries t=180,200,220,240,260,280s (tick 1800..2800), in this exact order: (1) role/economy contribution and repair; (2) boss spawn if tick 2600 and boss wave; (3) apply fighter+militia attack, vote B modifier 115/100 if active, integer floor; (4) calculate enemy retaliation from surviving ordinary HP and boss (5) apply guard block with vote A 115/100 or vote C 90/100, floors; (6) subtract damage from wall, overflow into townhall, stopping at zero; (7) emit canonical state and visual cues. For determinism, distribute damage to lanes in rotating order of starting lane = (combat_index mod 3), split attacks floor(amount/3) and distribute remainder in lane order; reallocate unused attack damage to other living subpools in same deterministic order. Within lane damage target priority runner, grunt, brute, boss. If boss pool remains but ordinary center subpools have HP, boss receives damage last.
Ordinary enemy retaliation before guard block: raw = ceil((10+3*d+9*isqrt(P))*ordinary_remaining/base_hp) when ordinary_remaining>0 else 0; boss surviving after spawn adds ceil((10+3*d+9*isqrt(P))/5). Apply guard block once to TOTAL and max(0,raw-guard_block). If current wall is zero, subsequent damage goes to townhall. If townhall becomes 0, mark DEFEATED immediately and skip all subsequent economic/combat resolutions, damage and XP for this wave; still settle exactly once at tick2800. If all pools empty before results, show CLEAR only if no boss spawn remains scheduled; on boss wave before tick2600 show BOSS INCOMING rather than CLEAR. Attack/retaliation do not happen during PREP or RESULTS.
At RESULTS enter (t=280) resolve once: victory iff townhall_hp>0 and all enemy pools zero, else loss. Victory reward wood min(cap,wood+100), stone min(cap,stone+60), food min(cap,food+50), consecutive_wins=min(10,consecutive_wins+1), consecutive_losses=0, total_wins++, village_level=min(50,1+floor(total_wins/3)); loss consecutive_wins=0, consecutive_losses++ capped at3, wood penalty min(wood,floor(wood/5)), stone penalty floor(stone/5), food penalty floor(food/5); vote C halves each penalty with integer floor. For defeat, wall_hp=max(250,wall_hp), townhall_hp=max(250,townhall_hp) but never above max; ensure at least 100 wood via max(100,wood) and cap. Results idempotent one-time event. At rollover, wave_number++, reset previous-wave roles/vote/enemies, preserve village progress, promote pending NEXT-wave registrations and start tick0 if present, otherwise WAITING.
Vote every EVEN wave, available [t=80,t=120), one latest ballot per player, exact A/B/C. Only current-wave participants can vote. A if wood>=50: deduct 50 wood at close, +15% guard block for wave; B if food>=50: deduct 50 food, +15% attack; C free, -10% guard block but reduces stock penalties on loss by 50%. A/B unavailable if insufficient resource at close: choose valid option with next highest votes, otherwise C. Tie: lexicographic A->B->C (deterministic, no RNG); zero votes: choose A if affordable else C. Vote decision applied exactly at tick1200, once, and displayed. No vote/more comments required to continue playing.

## Bounds and anti-spam
Role counts B/G/F can exceed population anchor, but effective counts for formula each capped at 10,000. Never repeat role contribution based on number of comments. Each ID is one player per wave, independent of comment burst. Send feedback only for accepted role/new choices and meaningful events; no invitation to flood or game stats based on comments count. Store alias opt-out and safety filtering. No paid combat advantage.

## Explicit fixtures / initial acceptance cases
One player XAY: NPC militia makes solo P=1 wave possible; 100 duplicate role comments create only one registration, not 100 workers. FIRST role change after initial join is allowed immediately; later changes require >=600 sim ticks after preceding change. At most one active role per player and boundary. Boss appears tick2600 before combat boundary, so two resolution opportunities at tick2600/2800. At tick2800 combat resolves BEFORE entering RESULTS. No viewer wave triggers WAITING not endless losses. No game clock catches up while provider is down. A role action at t=299.9s is assigned NEXT wave; replay must preserve acceptance tick exactly.

## Mandatory edge case resolutions
- New session WAITING has wave_tick=-1; first eligible join starts tick0 (no XP or combat on tick0). At tick3000 queued NEXT-wave roles start next wave tick0 automatically; if no queued participants, WAITING=-1.
- First valid role switch after initial join may happen immediately; subsequent role switches require >=600 simulation ticks from the last accepted switch. Same-role duplicates do not use the switch. No identity may occupy two roles at a boundary.
- Militia for 1<=P<=10 prevents 3-to-4 participant cliff without pretending NPCs are viewers. No rule guarantees victory to every all-builder/all-defender composition.
- At boss waves, ordinary HP=0 before tick2600 means BOSS INCOMING, never early victory. Final combat at tick2800 precedes RESULTS settlement. DEFEATED skips all remaining builder/combat/XP work, not just incoming damage.
- Victory increments total_wins and caps consecutive_wins at10; village_level=min(50,1+floor(total_wins/3)). Game math uses checked signed int64 and bounded resources. Tier20 clears construction_work, and no partial work consumes stone; at most one wall upgrade per boundary.
- Only one +10 XP per member per wave after an eligible contributing boundary. Progress is cosmetic only; no paid/gift power, repeat-chat XP, manufactured viewers or falsely victorious banners.
