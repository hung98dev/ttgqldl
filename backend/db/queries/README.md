# backend/db/queries

sqlc query sources. Generated Go lives in `backend/internal/db` and is never
hand-edited (`// Code generated by sqlc. DO NOT EDIT.`).

## Regenerating

sqlc cannot parse the goose migration files (they contain down migrations and
markers), so it reads the generated snapshot `backend/db/schema.sql`.

```bash
cd tooling
./migrate-up.ps1      # ensure the database is current
./schema-dump.ps1     # rewrite backend/db/schema.sql from the live schema
cd ../backend
sqlc generate         # sqlc v1.31.1, pinned in sqlc.yaml
```

`TestSchemaSnapshotMatchesDatabase` fails when `schema.sql` no longer lists the
same tables as the migrated database, which is the signal to run the two steps
above. Column-level drift is not detected by that test — regenerating the
snapshot is mandatory after any migration change.

## Rules

- Queries are added by the milestone that consumes them. A query must not be
  invented ahead of its owner (for example vote or checkpoint queries belong to
  M02/M04, not M01).
- Every query is schema-verified: `sqlc generate` fails on a column that does
  not exist, so a schema change breaks generation rather than production.
- Never edit `backend/internal/db/*.go` by hand; fix the query or the schema.
